# Archived issue write-ups

Historical findings and fix notes moved out of `docs/ISSUES_BUGS.md` during

## 2026-10-22 — Cost gate priced the default, not the plan (#262, #265)

Building the "What is Korean Saju?" short exercised the cost gate and the
image provider for real and found three defects.

- [x] #262 **HIGH — `ve estimate` priced the provider default, not the model
  the plan chose, and passed unpriced models silently.** Three separate gaps,
  all on the approve-before-you-spend path:

  1. The tiered planners record `props.image_model` / `props.motion_model`, but
     `requests_from_scene()` dropped them, so generation fell back to the
     provider default and `ve estimate` priced that default too.
  2. `_tally_costs()` resolved the model from `DEFAULT_PROVIDER_MODELS`
     unconditionally, ignoring a `model` already on the request.
  3. A model with no price in the registry returned `0.0`, which is
     indistinguishable from a free provider — so a plan using
     `nano-banana-2-lite` (recommended, unlisted) approved at **$0.00**.

  Fixed: requests carry the planned model (`_planned_model()` in
  `scene_assets.py`); `_resolve_model(..., explicit=)` lets the request's own
  model win; `estimate` now prints a per-line warning for any `$0.00` item whose
  provider is not in `FREE_PROVIDERS`; and `nano-banana-2-lite` /
  `nano-banana-2` were added to `pricing.yaml` and `models.yaml` (both
  $0.025/image) so the recommended tier is priced at all. Regression tests:
  `test_image_request_carries_the_planned_model`,
  `test_video_request_carries_the_planned_motion_model`,
  `test_estimate_prices_the_model_the_plan_chose`,
  `test_estimate_warns_about_an_unpriced_model`,
  `test_recommended_poyo_image_models_are_priced`. Verified end to end on the
  Saju plan: the gate now prices the plan's own model and voice
  (`nano-banana-2-lite` x7 = $0.175, `bulbul:v4-flash` = $0.023) instead of
  approving $0.00.

- [x] #265 **HIGH — every nano-banana image request failed at the provider.**
  `PoyoAIProvider._build_payload()` injected gpt-image's `size: "16:9"` and
  `resolution: "1K"` into *every* IMAGE payload. Nano-banana models take
  `aspect_ratio` and reject `size`/`resolution`, and PoYo's rejection message
  names the wrong field ("resolution is not supported by
  nano-banana-2-lite"), which sends you looking at the one parameter you can
  leave out. So the recommended budget model could not be used at all, for a
  vertical or any other aspect. Fixed: an IMAGE payload that already carries
  `aspect_ratio` gets no `size`/`resolution` default; gpt-image requests (no
  `aspect_ratio`) still get both. Regression tests:
  `test_poyo_build_payload_image_aspect_ratio_replaces_size`,
  `test_poyo_build_payload_image_custom_size_is_kept`. Verified live:
  `aspect_ratio: "9:16"` returns a 768x1376 still.
  Note for the routing doc: `nano-banana-2` at `resolution: "2K"` billed
  **8 credits** (~$0.04) per image, not the 5 credits / $0.025 the pricing
  table lists, and it letterboxes the image inside a 2048x2048 square canvas
  instead of returning a 9:16 file. `nano-banana-2-lite` bills 5 credits and
  returns a true 9:16 frame.

- [ ] #263 **MEDIUM — the TTS estimate assumes a single call.** Sarvam bills
  `ceil(chars / 1000)` **per call**, but `_tally_costs()` prices TTS once from
  the total character count regardless of how many requests the plan produces.
  `requests_from_scene()` emits one TTS request per scene, so a 7-scene,
  660-character job is really 7 calls (~$0.16) while the gate approved $0.023.
  ElevenLabs bills per character, so the current formula is right there; the
  fix needs a per-provider billing unit (`per_call` vs `per_char`) rather than
  a blind multiply. Not triggered by the Saju build, which synthesises the
  whole script in one call on purpose.

  **Partially resolved 2026-10-26:** the short path now prices every voice
  line as its own call (`price_short_job` and Task 7's `check_approved_spend`
  seam), because `ve short` really does make one call per line. The
  plan/explainer estimate still prices TTS once, which matches those paths'
  single narration call (see `test_estimate.py`'s "one TTS call for the whole
  script" case). What remains is the general per-provider billing unit, needed
  only if a plan path starts making per-scene TTS calls.

- [x] #264 **MEDIUM — a failed generation keeps its budget reservation.**
  `BudgetGovernor.allocate()` appends the estimate before the provider call;
  `record_actual()` only runs on success, and there is no release path. A PoYo
  400 therefore leaves its $0.025 in `spent` forever, in the running total and
  in the persisted `budget/budget.json`. Effect: `budget.json` over-reports
  what was spent, and a batch can trip `BudgetExceededError` on money that was
  never spent. The fix is a `release(estimate)` called from the manager's
  failure path with a test that a failed request leaves `spent` unchanged.

  **Fixed:** `AssetIngestionManager._release_estimate` settles an outstanding
  reservation at 0.0 on both failure paths — an exception or a provider-config
  error — and a placeholder returned by the last chain member is treated the
  same way. Regression test:
  `tests/test_budget_wiring.py::TestBudgetGovernor::test_a_failed_attempt_releases_its_reservation`
  proves a priced 2K image request that raises leaves `governor.spent == 0.0`.

- [x] #266 **MEDIUM — the estimate prices a music track for every plan, music
  or not.** `_tally_costs()` appends a `poyo_music` line whenever
  `music_provider` is non-empty, and the CLI default is `poyo_music`; nothing
  consults the plan. The Saju short is voice-only by brief, so the gate
  approved **$0.298** for a job whose real cost is **$0.198** — the extra
  $0.10 is a track the pipeline would never generate (`_should_run_music()` is
  gated on `music_prompt`). #262 fixed under-pricing; this is the same gate
  over-pricing, and it moves in exactly the direction that makes an approval
  meaningless. Workaround used here: `--music-provider ""`. Fix: price music
  only when the plan or the run asks for it (a `music` scene / `music_prompt`
  on the manifest), and give the flag a real "none" value instead of relying
  on an empty string.

  **Fixed:** `_tally_costs` now appends the music line only when the plan
  declares a `music_mood` **and** carries no `music_path` of its own. A
  voice-only plan estimates no track, and `--music-provider ""` remains the
  explicit opt-out. Regression tests:
  `tests/test_estimate.py::TestEstimateCommand::test_estimate_skips_music_when_the_plan_asks_for_none`
  and `..._when_the_plan_supplies_a_bed`.

- [x] #267 **HIGH — `ve cost-report` omitted every project that never wrote a
  `projects` row.** `cost_report()` joined `cost_lines` to `projects` with an
  INNER JOIN, so a hand-authored build that attaches the ledger through
  `JobContext` (and only ever writes cost lines) disappeared from the report.
  The `what-is-saju` job's 7 PoYo images ($0.175) and 3 Sarvam calls ($0.069)
  were invisible: the report showed `poyo_ai image 0.0000` for a job that had
  spent real money, while a raw `SELECT` on `cost_lines` showed all ten rows.
  Fixed with a LEFT JOIN (`template` filters still exclude them, since a
  missing project has no template) and a regression test;
  `ve cost-report --provider poyo_ai` now reports 28 calls / $0.1750.

- [x] #268 **HIGH — Silero VAD silently drops a quiet synthetic tail, and every
  caption in the final sentence then shares one timestamp.** On the
  `saju-zodiac-animal` narration, `transcribe_audio(..., vad_filter=True)` cut
  the audio at 34.54 s and never returned "Find yours free at Cosmic Sah-joo
  dot com.", so the closing sentence (2.6 s of speech, the CTA) had no
  recognised span. `_offset_to_time`'s "fall back to the last recognised span"
  path then mapped all nine display words onto `34.54`, and the caller's
  "a word is current until the next one begins" pass made the closing scene
  0.16 s long — the end card flashed for a single frame. Nothing raised: the
  transcript was valid, the timeline was valid, only the timings were degenerate.
  Fixed in `apps/transcribe` by giving `transcribe_audio` `initial_prompt`
  (prime the decoder with the spoken text) and `vad_filter` (default stays
  `True`; callers opt out), with a test that both reach `model.transcribe`
  verbatim. The kwargs dict is built conditionally so a fake model with the
  older signature still works. The build also gained `_spread_pinned_tail()` as
  a second line of defence: a trailing run of identical starts is spread over
  the remaining audio, weighted by word length. After the fix the same clip
  timed every word of the CTA and speech ended at 37.12 s.

- [x] #269 **HIGH — image pricing had no resolution dimension, so a 2K render
  was estimated and booked at the 1K rate.** `PricingRegistry` stored one
  `cost_per_image` per model and `BudgetGovernor.allocate()` received
  `provider`/`task_type`/`model`/`char_count`/`duration_s`/`count` — never
  `model_kwargs`, which is where `resolution` lives. PoYo's `gpt-image-2.5-fixed`
  bills **1.7 credits at 1K, 6 at 2K, 8 at 4K** (dashboard and the account's
  generation export). The registry held the 1K number ($0.0085), so this job's
  images were approved at $0.068 and booked at 5 x $0.0085 = $0.0425 against
  **30 credits ($0.15)** actually billed — a 3.5x under-report on the one number
  a cost gate exists to control.

  Fixed with a per-model price table keyed by a request attribute. A model may
  now declare `price_by: {resolution: {2K: {cost_per_image: 0.03}}}`, and
  `get_model_cost(provider, model, params=...)` merges the matching tier over
  the base entry (case-insensitive, `model_kwargs` first, an unknown tier falls
  back to the base rate so nothing is ever priced at $0.00). `unit_cost`,
  `estimate_image_cost`/`_video_cost`/`_music_cost`, `estimate_cost`,
  `BudgetGovernor.allocate`/`can_afford`, and `ve estimate` all take `params`;
  `_budget_context` forwards the request's own, and `requests_from_scene` turns
  a plan's `image_resolution` / `image_size` / `image_quality` props into
  `model_kwargs`, so a plan declares its tier instead of the gate assuming one.
  `models.yaml` now carries the three `gpt-image-2.5-fixed` tiers.

  Verified: the same plan quotes $0.24 for eight 2K stills (was $0.068) and the
  governor reserves $0.03 per 2K request (was $0.0085), so `budget.json` and
  `ve cost-report` now agree with PoYo's export. Two follow-ups filed: #270
  (quality x resolution models such as `gpt-image-2` need composite tiers) and
  #271 (a plan cannot declare a *reused* still, so the count is still scenes,
  not images). The cache-key lesson stands regardless of pricing: changing
  `RESOLUTION` mid-job invalidates every cached still
  (`AssetRequest.cache_key()` hashes `model_kwargs`), so **pin the tier before
  the first paid call** — this job paid 5 x 1.7 for a discarded 1K pass and
  5 x 6 for the 2K set.

- [x] #270 **MEDIUM — quality x resolution models had no composite price tiers.**
  `gpt-image-2` (the default image model) prices on a 3x3 quality x resolution
  matrix — low 1K $0.010 / 2K $0.020 / 4K $0.040, medium $0.042 / $0.045 /
  $0.081, high $0.169 / $0.178 / $0.321 — but the registry held only the
  1K-low scalar and the matrix lived in a `models.yaml` note. A
  `quality: high, resolution: 4K` hero frame (64 credits) was estimated and
  reserved at **3% of its bill**: the same defect class as #269 with a bigger
  error, and it covered the model every plan gets by default.

  Fixed by making the #269 mechanism recursive: a tier entry may carry its own
  `price_by`, and `_apply_price_variant` drops the axis it just resolved and
  recurses into the matched entry (depth-capped at 4 so a self-similar config
  cannot loop). Each level falls back to *its* base rate, so quality alone
  quotes the quality 1K cell, and an unpriced resolution keeps the quality rate
  instead of dropping to the cheapest cell. The matrix is now data in
  `models.yaml` (mirrored in `_BUILTIN_DEFAULTS` and generated into
  `pricing.yaml`); the plan surface was already there, because `_IMAGE_KWARG_KEYS`
  maps `props.image_quality` to `model_kwargs`.

  Verified: `quality: high` + `resolution: 4K` quotes $0.642 for two stills (was
  $0.02), `high` alone $0.169, `medium` + an unpriced `8K` $0.042, and the
  case-insensitive lookup accepts `HIGH`/`4k` as PoYo spells them.

- [x] #271 **LOW — the cost gate counted scenes, not images, when a plan
  reuses a still.** `saju-zodiac-animal` shows five stills across eight scenes
  by pointing scenes 004/006/008 at another scene's image via
  `props.image_scene`, but nothing in the engine knew that key, so
  `requests_from_scene` emitted an image request per scene and the estimate
  priced eight 2K stills ($0.24) for a five-still job ($0.15).

  Fixed at the plan level rather than the scene level, because only the plan
  knows whether a target exists. `resolve_image_reuse(plan)` maps each reusing
  scene to the scene that *owns* the still, following chains and dropping a
  missing target or a cycle (the scene then generates its own still — a typo
  costs one render, never a blank scene). `requests_from_plan` is the new entry
  point for pipelines and the cost gate: it skips the IMAGE request for those
  scenes, so one still is one request. `attach_results_to_plan` then copies the
  owner's IMAGE result into the reusing scene under its own asset id and
  `metadata.reused_from`, because every renderer reads `scene.assets` and none
  of them knows about `image_scene`.

  Verified: a four-scene plan with two reuses quotes one image line for two
  stills; `ve assets` and the engine `assets.resolve` handler both use the
  plan-level helpers, so the renderer and the ledger see the same five stills.
  `props.image_scene` is the canonical key; `props.reuse_image_from` is accepted
  as an alias.

## 2026-10-26 — Slice 2: content pack and `ve short` (#272)

- [x] #272 **HIGH — the first paid content-pack build failed its own
  loudness gates after normalisation ran.** `ve short` finished
  `saju-v1-your-animal` (42.5 s, 5 stills, 7 voice lines) with 13/15 QA
  checks green and `QA: FAIL`: `loudness -15.1 LUFS (target -14)` and
  `true_peak -0.9 dBTP (ceiling -1)`. The failure table's "normalisation
  skipped" cause did not apply — `normalize_loudness` had run; its single
  `loudnorm=I=-14:TP=-1:LRA=11` pass reported `normalization_type: dynamic`
  with `target_offset 1.18` against a narration that was already hot at the
  peak (-16.31 LUFS / -0.35 dBTP). Single-pass loudnorm refuses to apply the
  +2.31 dB the bed needs because that would push the peaks over the ceiling,
  so it lands short of the target.

  Fixed by normalising against the *encoded* file: measure the input, apply
  the exact gain behind a look-ahead limiter set at -1.7 dBTP (0.7 dB of
  headroom for AAC's ~0.4 dB decode overshoot), measure the encode, and
  correct the residual from the original (up to three passes; only the last
  file is kept, so the shipped audio has one AAC generation). Target and
  tolerance are unchanged; `TRUE_PEAK_DB` was removed because the limiter
  ceiling replaces it. `tests/test_loudness_normalization.py` pins both a
  hot-peak source and an already-settled one: the hot source measured -22.99
  LUFS under the old code (red) and -14.1 / -1.7 after the fix.

  Verified on the real build: re-running with every asset cached (12/12
  `status=cached`, $0.00 incremental) produced `loudness -14.5 LUFS`,
  `true_peak -1.3 dBTP`, and **QA PASS 15/15** on the same 42.5 s file.

- [x] #273 **MEDIUM — the short path's paid calls reached the project ledger
  without a price or a job id.** All 24 `cost_lines` rows from the first
  content-pack build carried `project_id='saju-v1-your-animal'` but
  `job_id=NULL` and both cost columns NULL, so `ve cost-report` counted the
  12 paid calls and attributed **$0.3110** as $0. The cause:
  `short_pipeline._resolve` built the `AssetIngestionManager` without a
  `BudgetGovernor`, so `_attempt_provider` never produced a
  `BudgetEstimate` and `_record_cost_line` had no price to record; the row
  also never carried the request's `job_id`.

  Fixed by pricing the row from `PricingRegistry` when no `BudgetEstimate`
  exists (`AssetIngestionManager._request_cost`), passing
  `job_id=request.job_id`, and recording a cache hit as 0.0 rather than NULL.
  A governor was deliberately not used: the short path calls `_resolve` once
  for stills and once for voice, and a fresh governor per call would overwrite
  `budget/budget.json` with only that batch's spend. The 24 historical rows
  were backfilled from the approved line items ($0.15 images + $0.161 voice;
  cached rows 0), so `ve cost-report` now reports $0.6885 poyo_ai image and
  $0.3680 sarvam_tts across the account. Regression test:
  `tests/test_budget_wiring.py::test_cost_lines_carry_the_job_id_and_the_registry_price`.

## 2026-10-22 — Video motion-quality pass (#240–#247)

A review of `human-body` and `solar-system-explainer` v2 found that both read
as animated slides: each diagram drew itself at scene start and then held
still while the narration talked over it. These are engine fixes, so every
pipeline that renders through motion_graphics, the render graph or
scene_plan_composition benefits. Guide: `docs/VIDEO_MOTION_QUALITY.md`.

- [x] #240 **Motion-graphics scenes froze after their entrance animations.**
  `freezedetect` found four 1.5–1.8 s holds in the 31 s solar v2. Fixed: diagrams
  and code highlights get an `ambient` layer (`"glow"` by default, or a
  `"stars"` parallax field) and a slow `camera_drift` pan; circle nodes
  breathe. The QA skill now runs `freezedetect` (`no_frozen_frames`;
  advisory unless `QASkill(freeze_max_seconds=…)` is set). Solar v3 has no
  freezes ≥1.5 s.
- [x] #241 **Visuals were not synced to the narration.** Every reveal fired
  on a fixed stagger from scene start. Fixed: new `video_editor_core.cues`
  (`find_cue`/`resolve_cues` map a spoken phrase to its time) plus `at`
  (reveal time) and `emphasize` (pulse times) on diagram nodes, edges and
  orbits.
- [x] #242 **The HyperFrames compiler dropped `shape` layers.** The router
  sends graphs with `shape` layers to HyperFrames, but
  `hyperframes_project._clip_html` skipped them with a warning, so they never
  rendered. Fixed: `shape` renders as a rounded box or circle, and
  `effect="spotlight"` pops in, breathes and fades out.
  `cues.spotlight_layer()` builds one, which lets you ring part of a
  still or chart on cue.
- [x] #243 **Hand-written compositions fell back to a serif font.**
  human-body's `compose.py` set no `font-family`, so titles and captions
  rendered in Chrome's default Times. Fixed for that build: it now uses the
  engine's `font_face_css` + `font_stack`, and its captions come from the
  engine's karaoke pass instead of a two-sentence paragraph box. Rule:
  compositions must take fonts and captions from the engine.
- [x] #244 **Karaoke captions gave no read-ahead cue.** Only the active word
  changed colour. Fixed: `CaptionStyle.upcoming_opacity` (karaoke preset:
  0.6) dims words not yet spoken, the active word pops (`ve_word_pop`) and
  each line slides in (`ve_line_in`). Follow-up: karaoke is now the default
  `CaptionStyle()` for every brandless video; the old Coolvetica look is
  `CaptionStyle.preset("pop_in")`. Karaoke routes captioned graphs to
  HyperFrames.
- [x] #245 **Ken Burns repeated the same linear push on every still.**
  Fixed: `scene_plan_composition` cycles zoom-in, pan-right, zoom-out and
  pan-left with ease-in-out, always scaled ≥1.02 so no edge shows.
- [x] #246 **Diagram edges ran centre to centre and could not show
  direction.** Fixed: edges are clipped to the node outlines and draw on
  from source to target (`stroke-dashoffset`); an optional `arrow` head
  fades in at the end of the draw.

- [x] #247 **Text sat under platform UI on vertical video.** The
  `tiktok_raw`, `vlogger_shorts` and `shorts_factory` presets put captions at
  y=1720–1880 of 1920, which is under the TikTok/Shorts description bar, and
  nothing in the engine knew about safe zones. Fixed: new
  `video_editor_core.safe_area` (vertical keeps the bottom 20 % and 8 %
  margins clear; landscape uses 5 % title-safe). The planner and
  `CaptionsSkill` fit text into it, all presets were moved inside it (a test
  enforces this), the pipeline logs violations, and QA adds an advisory
  `text_in_safe_area` check (`safe_area_strict=True` makes it fail). Preset
  caption blocks were also switched to karaoke to match the new default.

## 2026-10-22 — Full integration pass: stale + wrong patterns (#251–#260)

A complete integration run of both pipelines (raw-footage `ve run` and
script-to-video `plan-script → assets → render`), plus a CLI-surface sweep,
found five defects that unit tests could not see because each sits at a
**seam** between two components, plus five stale/wrong patterns (#256–#260)
that the sweep surfaced. All ten are fixed with regression tests; the pattern
fixes are recorded under "Resolved the same day" below.

### Fixed

- [x] #251 **CRITICAL — `ve run` exported the rough cut, not the polished
  render.** `ExportSkill` guessed its input from a hardcoded search list whose
  first entry was `music/with_music.mp4` and whose last was
  `rough_cut/locked.mp4`. On a run *without* background music the v2 pipeline
  writes `graph/composed.mp4` (graphics + captions in one render-graph pass),
  which was **not in the list at all**, so the search fell through to the
  locked rough cut. Confirmed on a real job: `final.mp4` was byte-identical to
  `rough_cut/locked.mp4` (md5 `fd67715e…`) while `graph/composed.mp4` was
  `6df25791…` — the delivered file had no graphics and no captions. Fixed on
  two sides: `DEFAULT_INPUT_SEARCH` now leads with `graph/composed.mp4` and
  ranks `broll/` below `graphics/` (b-roll is applied earlier in the chain);
  and `pipeline.py` passes the video it actually produced as an explicit
  `input_video=`, so correctness no longer depends on list order. Tests:
  `test_default_input_search_prefers_render_graph_output`,
  `test_export_uses_explicit_input_video`, and an end-to-end
  `test_export_ships_the_composed_render_not_the_rough_cut` that asserts the
  bytes match.
- [x] #252 **HIGH — `--qa` failed every vertical preset.** The QA and review
  gates were defaulted to a 16:9 expectation everywhere, but `short_explainer`
  and `tiktok_raw` render 1080×1920. `ve run --preset short_explainer --qa`
  therefore reported `aspect_ratio` failure on a perfectly good 9:16 output.
  Fixed: `_preset_aspect_ratio()` reads `aspect_ratio` out of the active
  preset JSON, and `run()` derives `--expected-aspect-ratio` from the preset
  the router actually selected (falling back to the template's declared
  aspect, then 16:9). The flag is still available for overrides; the QA gate
  now passes with no flag at all. Test: `TestPresetAspectResolution`.
- [x] #253 **HIGH — the HyperFrames JSON-plan contract no longer exists.**
  `hyperframes_cli.render_segment()` invoked `hyperframes render --input
  plan.json --output …`; HyperFrames 0.8 removed `--input` (verified against
  the installed CLI: `Unknown flag: --input`, exit 1). The graphics skill
  routed every segment without a pre-rendered source through this call, so
  the failure surfaced as a segment render error. Fixed: `render_segment`
  now delegates to `render_project` (directory + `-o`) and rejects a JSON
  plan with an explicit `RenderSegmentError` instead of shelling out to a
  flag that does not exist; `graphics/renderer.py` catches that error and
  degrades to its FFmpeg fallback, which is what the skill contract promises
  ("HyperFrames *or* FFmpeg"). Tests: 9 rewritten `test_hyperframes_cli`
  blocks plus `test_render_segment_rejects_a_json_plan` and
  `test_render_composition_segment_falls_back_when_hyperframes_fails`.
- [x] #254 **MEDIUM — `manifest.json` recorded roots the job was not using.**
  A fresh `JobManifest` carries `work_root="/work"` / `output_root="/output"`
  container defaults. `JobContext` built its `ArtifactStore` from the real
  roots but never wrote them back, so `manifest.json` claimed `/work` even
  for a job under `./projects` — and `JobContext.from_manifest` re-homed the
  job to `/work`. Fixed in `JobContext.__init__` by recording the actual
  roots on the store's manifest. Test:
  `test_job_context_manifest_records_actual_roots` (round-trips through
  `from_manifest`).
- [x] #255 **LOW — stale Remotion references in shipped docs.** The Remotion
  renderer was retired, but `workflows/explainer_from_script.md` still told
  users to install the Remotion dev stack and passed removed flags
  (`--force`, `--composition-id`), `workflows/raw_to_short_one_command.md`
  listed Remotion for Node tooling, `README.md` documented an `engine/`
  directory that is now `packages/core` and a `sfx` skill that no longer
  exists, `pyproject.toml` keyworded `remotion`, and
  `scene_plan_composition.py`'s docstring still called itself "the analogue
  of the Remotion ScenePlanComposition". All rewritten. `explainer_from_script.md`
  now also documents the required `--config` and the stub-provider path that
  actually works without API keys.

### Resolved the same day

- [x] #256 **MEDIUM — the Jev low-value classifier had no floor.** The
  semantic-removal pass fed its regions straight into `_build_kept_segments`
  with no cap on how much of the take it could delete. On the demo fixture it
  flagged `[[0.0, 11.4], [12.0, 13.3]]` and kept only 13.4–16.4 s — **71 % of
  the input removed**, reported as success. Fixed with two bounds, both
  defaults and both overridable through `RoughCutSkill(...)`:
  `SEMANTIC_MAX_REGION_SECONDS = 8.0` (a single "low value" verdict longer
  than that is distrusted and kept) and
  `SEMANTIC_MAX_REMOVAL_FRACTION = 0.35` of the take. Regions are accepted in
  confidence order, so a tight budget keeps the clearest wins; a clamp logs
  `semantic_removal_clamped`. On the demo fixture the 11.4 s region is now
  kept and only the 1.3 s false start is cut; `max_removal_fraction=1.0` with a
  large region ceiling restores the old behaviour. Tests:
  `tests/test_rough_cut_jev.py` (5 new).
- [x] #257 **MEDIUM — `ve assets` requested motion at the raw scene length.**
  `scene_assets.py` passed `duration_seconds: scene.duration_seconds`
  unclamped while the storyteller path used the #250 clamp. The rule moved to
  `video_editor_engine.models.motion.motion_duration_for()` and both paths now
  call it, so a 20 s scene asks for a 10 s clip (looped at render time) and a
  1 s scene still asks for the 4 s minimum. The flag split was real but
  narrower than filed: `requires_motion` is the *intent* a script-to-video
  planner records and `needs_motion` is the *state* the storyteller records
  once a clip landed. `scene_wants_motion()` now reads either, with an
  explicit `requires_motion` authoritative, so a storyteller plan fed through
  `ve assets` generates video. Verified end to end: a plan with
  `props.needs_motion=true` now resolves a VIDEO asset. Tests:
  `tests/test_asset_ingestion.py` (5 new), `tests/test_scene_assets.py`.
- [x] #258 **MEDIUM — `ve plan-script` had no config discovery.** Omitting
  `--config` exited with "LLM router requires --config..." even with a repo
  `config.yaml`. Fixed with `_discover_config_path()`: explicit flag →
  `VE_CONFIG` → `config.yaml` in the working directory or any parent → repo
  root. Verified from the repo root and from a nested package directory. When
  nothing is found the error now names the places searched. Tests:
  `TestConfigDiscovery` in `tests/test_cli.py` (7).
- [x] #259 **LOW — stock video was selected without regard to scene length.**
  Pexels and Pixabay returned the first search hit, so a 4 s scene could
  download a 61 s clip. Both providers now call
  `providers/visual/_selection.choose_by_duration()`: the shortest clip that
  still covers the scene, else the longest available, else the provider's own
  order (unchanged when the request carries no duration). Tests:
  `tests/test_pexels.py`, `tests/test_pixabay.py` (5).
- [x] #260 **LOW — container path defaults and a store path heuristic.**
  Added `video_editor_cli.paths`: every command now resolves roots as explicit
  flag → `VE_WORK_ROOT` / `VE_OUTPUT_ROOT` → `/work` `/output` when mounted →
  `./projects` `./outputs`. `main.py`, `payloads.py`, `estimate.py`,
  `preview.py`, `finalize.py` and the enqueue/worker payload path all use it,
  so no command needs `--work-root` on a developer machine. `ArtifactStore`
  now takes the real `output_dir` and `JobContext` supplies its `output_root`,
  so `store.output()` no longer has to guess from the work path (the naming
  heuristic remains as a fallback for callers that do not pass one).
  `src/video_editor/__init__.py` is **not** dead: it is the workspace root
  package and the hatch wheel target, so removing it breaks `uv sync`; it
  stays. **Follow-up the same day:** the resolution moved down to
  `video_editor_state.paths`, and `JobContext` / `JobManifest` now default
  through it instead of hardcoding `/work` / `/output` — the library-level
  half of the same trap, which the engine, MCP server and ad-hoc scripts hit
  whenever they build a context without passing roots. The worker's
  "falling back to /work" warning became a note naming the roots it will
  actually use. Tests: `TestDefaultRoots` (4) and four `JobContext` /
  `JobManifest` default-root tests.

## 2026-10-22 — Feasibility review: motion-asset fallback + overlay timing (#248–#250)

Reviewing `../tool-lab/trials/2026-10-22-motion-canvas-local-i2v/README.md` against
the current tree surfaced three engine defects that would have blocked the
Tier-A local-motion work. All fixed with regression tests; 1724 tests pass,
ruff and mypy clean.

- [x] #248 **A motion scene had no still to fall back to.**
  `build_storyteller_scene_plan` emitted *either* a VIDEO *or* an IMAGE
  request per scene, then resolved the batch all-or-nothing, so a failed
  motion clip failed the entire job and no still existed to degrade to. The
  feasibility doc assumed the opposite ("the image asset stays in the plan").
  Fixed: every scene now requests its still (motion scenes get both, and the
  renderer still prefers the video), the batch resolves via
  `resolve_partial`, TTS/SFX stay required, a scene's visual set must contain
  at least one surviving asset, and a failed clip logs
  `storyteller_asset_fallback`, flips `render_track`/`needs_motion` to the
  still and records the attempt in `motion_requested`.
- [x] #249 **A video overlay scheduled after t=0 never appeared.**
  `_video_filter_parts` passed a clip's frames to `overlay` with only an
  `enable` window. The clip decodes from its own t=0, so it played (and
  ended) at the start of the composition and was merely hidden; by the time
  the layer became visible it was already finished, and `eof_action=pass`
  showed the base through it. Confirmed against FFmpeg: a 2 s red clip
  scheduled at 5–7 s rendered black at t=5.5. Fixed:
  `_overlay_source_label` prepends `trim=duration=<window>` and
  `setpts=PTS-STARTPTS+<start>/TB`; stills and logos are unchanged. Smoke
  test now reads black (t=4.9) → red (t=5.5, t=6.9) → black (t=7.5).
- [x] #250 **Motion clips were always generated 4 s long, freezing the tail
  of longer scenes.** The VIDEO request hardcoded `duration_seconds: 4` and
  was resolved in the same batch as the TTS, so it could not know the scene's
  length — a scene is `tts_duration × 1.15`, routinely 6–12 s. Every clip
  therefore ended early and the renderer held its last frame, exactly the
  freeze `no_frozen_frames` QA reports. Fixed by splitting the batch: the
  still, TTS and SFX resolve first, `duration` is derived from the TTS result,
  and only then is the clip requested at
  `clamp(ceil(duration), MOTION_DURATION_MIN=4, MOTION_DURATION_MAX=10)`
  (the range every model in `VIDEO_TIER_MODELS` accepts; recorded as
  `motion_duration_seconds`). The HyperFrames compiler's `<video>` also gained
  `loop`, so a provider that returns a little short repeats instead of
  freezing. Tests cover the TTS-derived length, the clamp, and the `loop`
  attribute.

## 2026-10-22 — Local-skills capability test: solar-system explainer (#230–#239)

A 30s silent explainer built only from local engine skills
(`videos/2026-10-22/solar-system-explainer/`) exposed the bugs below. All were
fixed the same day and regenerated as `solar_system_explainer_v2.mp4` with a
Sarvam voiceover.

- [x] #230 **`motion_graphics` never rendered through HyperFrames.**
  `_render_via_hyperframes` called the legacy JSON contract
  (`hyperframes render --input plan.json`); HyperFrames ≥0.7 only renders HTML
  project dirs, so every clip silently took the ffmpeg fallback. Fixed: the
  plan compiles to an HTML composition (`_plan_to_html`) rendered with
  `render_project`. The HTML path also adds entrance animations
  (`enter`/`delay`), circle nodes, SVG edges and animated `orbit` layers
  (`DiagramSpec.orbits`).
- [x] #231 **ffmpeg fallback dropped every non-text layer.** Node boxes,
  callout bars and highlights were not drawn, and diagram labels use the
  background colour, so they were invisible. Fixed: rect layers render
  as `drawbox` fills; centred labels stay centred.
- [x] #232 **An apostrophe broke the ffmpeg fallback.** `_escape` emitted
  `\'` inside a single-quoted `drawtext` value, which unbalances ffmpeg's
  quoting (`Unable to parse "box" option value`). Fixed: text is written to
  per-layer files and passed via `textfile=`, so no escaping is needed.
- [x] #233 **The motion_graphics manifest misreported its renderer.** It said
  `"hyperframes"` whenever the CLI was on PATH, even after a fallback. Fixed:
  `MotionGraphicsSkill.last_renderer` records the path that actually ran.
- [x] #234 **Transitions failed on video-only clips.**
  `concat_with_transitions` always built `acrossfade` on `[i:a]`. Fixed:
  silent groups render video-only, and mixed groups pad the silent clips
  with `anullsrc`.
- [x] #235 **The render graph could not put a voiceover on a silent
  source.** `has_audio=False` dropped every audio bus, and `True` read a
  non-existent `[1:a]`. Fixed: `RenderGraph.emits_audio`; buses mix over an
  `anullsrc` bed when the source is silent.
- [x] #236 **The Sarvam key name did not match `.env`.** The provider read only
  the misspelled `SARAVAM_API`, while `.env` uses `SARVAM_API` (also flagged
  in AUDIT_2026-08-04). Fixed: both names are accepted and the configured one
  wins.
- [x] #237 **An unlabeled diagram node failed lint.** A node with `label: ""`
  (for example a plain circle) emitted an empty text layer, and
  `lint_plan` rejected the whole plan. Fixed: unlabeled nodes get no
  label layer.
- [x] #238 **Diagram edges were drawn over their nodes.** `_diagram_layers`
  appended edges after the nodes, so the centre-to-centre lines were
  painted across the node boxes and labels. Fixed: edges are emitted
  before the nodes and render underneath them.
- [x] #239 **Every HyperFrames render waited 45 s for nothing.** The
  compositions from `hyperframes_project`, `scene_plan_composition` and
  `motion_graphics` animate with plain CSS but lacked `data-no-timeline`.
  HyperFrames therefore polled 45 s for a `window.__timelines` registration
  on every render (its own lint flags this as `missing_timeline_registry`).
  Fixed: all three root elements set `data-no-timeline`. A probe render went
  from 47.4 s to 2.1 s, and the full explainer build from about 6 min to
  about 80 s.

Also added on 2026-10-22: **karaoke captions.** `CaptionStyle.preset("karaoke")`
(or a brand with `caption_animation: "karaoke"`) renders Montserrat ExtraBold
with a soft shadow and highlights each word in `highlight_color` while it is
spoken. Word timings travel on the render-graph text layer (`style.words`),
and the HyperFrames compiler emits per-word CSS animations. Inter and
Montserrat are now bundled (OFL) in `video_editor_core/fonts/` and embedded
via `@font-face`, so captions and motion graphics no longer depend on
installed fonts. A new `text_effect: "shadow"` option replaces the glyph
stroke, which ate into thin letters.

Observed, not a code bug: Sarvam returned HTTP 400 for `bulbul:v4-flash` on
every request this session; the provider's built-in fallback to `bulbul:v3`
produced the audio.
