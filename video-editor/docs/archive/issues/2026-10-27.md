## 2026-10-27 — Full audit, phase 3 `agy` upgrade (#291–#293, #295)

- [x] #291 **MEDIUM — callers sent `agy` no aspect.** `AssetRequest.aspect()`
  derives the framing from `width`/`height`, `aspect_ratio` or a provider preset;
  `_aspect_line` uses it and `_verify` rejects a result more than 3 % off. The
  short, scene-plan and storyteller callers all carry the canvas.
- [x] #292 **MEDIUM — a degraded `agy` cost 10 minutes per still.** The manager
  runs one preflight per run (binary, supported 1.4.x/1.x version, 20 s auth
  probe) and drops `agy_image` for the run if it fails. The breaker opens a
  30-minute window for agy, and quota/auth errors trip it immediately.
- [x] #293 **LOW — wrong provenance.** Results now record `agy_version`,
  `driving_model`, `image_model` (from the structured reply), `quota_units: 1`
  and `cost: 0.0`.
- [x] **Structured call.** `--output-format json` + `--json-schema`,
  `--disable-slash-commands`, `--effort low`, a configurable
  `gemini-3.8-flash-low` driver and `--print-timeout`; the reply must contain
  `path`, `width`, `height`, `image_model`, and `_verify` remains authoritative.
- [x] **Restricted profile.** `provider_options.profile_dir` (default
  `~/.config/video-editor/agy-profile`) is a dedicated `HOME` with auth sym
  links, a command-deny settings file and a `PreToolUse` guard. `ve agy-setup`
  installs it. Verified against `agy` 1.4.8: settings alone did not confine
  writes, so the hook is the boundary.
- [x] **Batching.** `AGYSession` keeps a `stream-json` process per manager batch
  (max two, one turn at a time); a dead session falls back to a one-shot call.
- [x] **Draft vs final chain.** `assets.image_chain_final` is
  `[poyo_ai, openrouter, fal_ai]`; `--final` on `ve short`, `ve explain`, `ve run`,
  `ve assets` and `ve estimate`, and `payload.final` in the worker, select it.
  Estimates and `max_images_per_run` use the selected chain.
- [x] #295 **MEDIUM — an `agy` child outlived an abruptly stopped parent.**
  Every agy child now gets Linux `PR_SET_PDEATHSIG`; sessions also close at the
  end of each resolve batch.
- [ ] **Live image check deferred:** the account's `generate_image` quota is
  exhausted (`429 RESOURCE_EXHAUSTED`, reset in ~67 h), so the structured
  stream and guard were exercised against real `agy`, but a real PNG could not
  be produced in this session. The fake-agent suite covers the file/verify leg.

## 2026-10-27 — Full audit, phase 2 fixes (#278, #279, #281–#284, #287, #297)

- [x] #278 **MEDIUM — worker payload paths were partly unchecked.**
  `media_dir`, `music_path`, `presets_dir`, `transcript_path`, `lyrics`, `source`
  and the FableCut/ComfyStudio `project_dir` all resolve inside the job's work or
  output dir. `work_root`/`output_root` are checked against the configured
  `VE_WORK_ROOT`/`VE_OUTPUT_ROOT` data roots before the context is built.
  `_validate_payload_paths` and its string-prefix check are deleted.
  Regression: `tests/test_worker_payload_paths.py`,
  `tests/test_engine_integration.py`.
- [x] #279 **MEDIUM — one subprocess path.** Every `subprocess.run` in `apps/`,
  `packages/` and `skills/` now goes through `video_editor_ffmpeg.run.run_ffmpeg`
  or `run_subprocess`; the shared wrappers carry `PROBE_TIMEOUT_SECONDS` /
  `RENDER_TIMEOUT_SECONDS` and typed errors. `video_editor_ffmpeg.probe.probe_duration`
  replaces the duplicated ffprobe parsers (including the four script copies).
  Ruff `TID251` bans the `subprocess` module outside `run.py`, the preview
  server, `scripts/` and tests. `tests/test_subprocess_timeouts.py` remains a
  belt-and-braces scan.
- [x] #281 **MEDIUM — silent stub fallbacks.** `assets.strict` (default true)
  makes an unservable `auto` request and a failed terminal `fal_ai` attempt
  raise instead of returning a placeholder; explicitly named stubs still work,
  `strict: false` restores the old behaviour. QA now fails a build whose cache
  contains a `stub_*` provider: `skills/qa`, `ve short` and `ve explain` all add
  a `no_stub_assets` check and carry the ids into `qa.json`.
- [x] #282 **MEDIUM — MCP handlers blocked the event loop.** Synchronous skill
  runs go through `asyncio.to_thread`. (`run_pipeline` → queue is phase 6.)
- [x] #283 **MEDIUM — cost and budget failures were logged, not surfaced.**
  `AssetIngestionManager.cost_tracking_degraded` is set by the pricing,
  budget-snapshot and ledger-write failure handlers. The reasons are written to
  `work/<job>/cost_tracking_degraded.json`, recorded as a
  `COST_TRACKING_DEGRADED` ledger issue, added to `qa.json` as a warning, and
  `ve cost-report` names the affected projects. `unpriced_count` remains.
- [x] #284 **MEDIUM — blocking SQLite in async methods.** `PersistentJobQueue`
  runs every DB call in `asyncio.to_thread` (`check_same_thread=False`, same
  lock). The ledger has no async API and is unchanged.
- [x] #287 **LOW — whole-file copies through memory.** 19 sites use
  `shutil.copyfile`.
- [x] #297 **MEDIUM — fresh queue databases could not be initialised by several
  workers.** `_init_db` created the table, then each process ran
  `ALTER TABLE … ADD COLUMN`; losers failed with `database is locked` or
  `duplicate column name: heartbeat_at` (17 of 20 trials with 8 processes).
  New databases now declare both columns, the busy timeout is set before WAL,
  and schema creation retries lock/duplicate-column races. Regression:
  `tests/test_queue_multiprocess.py`.
- [x] **Test isolation:** the CLI's module-level in-memory queue leaked a job
  from `test_enqueue_accepts_valid_json` into the next test's worker; an autouse
  fixture now resets it.

## 2026-10-27 — Full audit, phase 0–1 fixes (#274–#277, #280, #294–#296)

Findings from `docs/archive/audits/AUDIT_2026-10-27.md`; plan in
`~/.claude/plans/now-complete-planning-for-jazzy-hinton.md`. Remaining audit
items (#278–#279, #281–#293, A1–A8) are still open there.

- [x] #274 **HIGH (latent) — `PersistentJobQueue.dequeue` handed one job to
  every process that asked at once.** Select-then-update with no status guard;
  4 processes on one job all claimed it in 40/40 trials. Latent today: the CLI's
  `_get_queue()` still returns the in-memory queue. Fixed: one guarded
  `UPDATE … WHERE status = 'pending' … RETURNING *` inside `BEGIN IMMEDIATE`.
  Regression: `tests/test_queue_multiprocess.py` (fails 4/4 on the old code).
- [x] #275 **HIGH — crashed jobs stayed `running` forever.** `requeue_stale`
  had no caller. Fixed: a `heartbeat_at` lease column (migrated in place),
  `JobQueue.heartbeat()`, `requeue_stale` measured from the last heartbeat and
  applied with one guarded update, and `ve worker` sweeps before each dequeue
  and heartbeats while a job runs. The lease length is the new
  `queue.stale_seconds` setting (default 900); `--stale-seconds` overrides it.
  A stale job that exhausts `max_retries` is dead-lettered instead of being
  requeued forever.
- [x] #276 **HIGH — MCP built job paths from an unvalidated `job_id`.**
  `JobContext` now refuses ids that are empty, `.`/`..`, over 200 chars, or
  contain a separator or control character (`validate_job_id`). MCP jobs live
  under `<data root>/mcp/<job_id>` (`video_editor_mcp/context.py`) instead of a
  never-cleaned `mkdtemp`; `run_skill`'s `work_root`/`output_root` and every
  media/transcript argument must sit inside the data roots (no more
  `/tmp/ve-<job_id>` default). `JobContext` also resolves both job dirs and
  refuses a symlinked dir that escapes its root.
- [x] #277 **HIGH — MCP generation had no spending cap.** New `mcp:` config
  section (`default_budget_usd` 1.00, `per_call_cap_usd` 0.50). Every MCP job
  carries a USD-priced `BudgetGovernor`; a caller's `budget` can only lower
  it; asset tools price the request first and refuse above the per-call cap
  without `approve_usd`, and return `estimate_usd`. `broll` runs under the job
  budget. The section is in both `config.yaml` and `config.example.yaml`.
  `dubbing` constructs no provider unless a caller injects one, so the shipped
  server cannot spend there.
- [x] #280 **MEDIUM — `agy` output was published with a cross-filesystem
  `shutil.move`.** Now copied to a hidden sibling and `os.replace`d.
- [x] #294 **LOW — stale `agy_image` module docstring.** Updated.
- [x] #295 **MEDIUM — an `agy` child outlived an abruptly stopped parent.**
  Fixed with a Linux `PR_SET_PDEATHSIG` preexec on every agy child; the stream
  sessions are also closed at the end of each manager batch. See the phase 3
  section above.
- [x] #296 **MEDIUM — MCP routing tests could reach real providers.** The old
  MCP helper handed the manager a deleted temp dir, so asset calls failed fast
  by accident; with real job dirs the routing tests walked the configured image
  chain (real `agy`, then paid PoYo with the `.env` key) and wrote into the
  real `projects/`/`outputs/`. Fixed: `tests/conftest.py` hides a bare `agy`
  from every test unless `VE_AGY_INTEGRATION=1`; the MCP test modules point the
  data roots at `tmp_path` and stub `AssetIngestionManager.resolve`. No paid
  call was made (the only provider reached was `agy`).
