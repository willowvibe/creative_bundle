## 1. Architecture & Design

### A1. **CRITICAL — `main.py` is a 3,951-line god file**

`apps/cli/src/video_editor_cli/main.py` contains:
- 40+ Typer CLI command definitions
- 20+ worker `_handle_*` dispatch functions
- 15+ Pydantic payload models
- Utility functions, structlog config, dotenv loading
- The entire `ve worker` loop

**Impact:** Every CLI change risks merge conflicts. New contributors cannot
find their way. The file is too large for any LLM to hold in context at once,
making future AI-assisted development unreliable.

**Fix:** Split into:
- `main.py` — app creation + top-level config only (~100 lines)
- `commands/` — one file per command group (ingest, assets, export, ledger, etc.)
- `worker.py` — worker loop + handler registry
- `payloads.py` — all Pydantic payload models
- `handlers/` — one file per handler family

### A2. **CRITICAL — `test_cli.py` is a 3,555-line test monolith**

Same problem as A1 but for tests. 76 test functions in one file.

**Fix:** Split into `tests/cli/` with one file per command group, mirroring
the proposed `commands/` split.

### A3. **HIGH — No MCP server exposing the engine**

The engine has a rich CLI and worker dispatch system, but no MCP server.
Claude Code and other AI agents must shell out to `ve` subprocesses, which
is slow, fragile, and loses structured context.

Every major competitor (Kinocut: 150 tools, NIRA: 55 tools, CutAI: MCP server,
video-creator-mcp: 31 tools) ships an MCP server.

**Fix:** Build a `video-editor-mcp` package that wraps:
- `SkillsPipeline.run()` → `run_pipeline` tool
- Individual skills → `rough_cut`, `captions`, `music`, `export` tools
- Asset providers → `generate_image`, `generate_tts`, `generate_music` tools
- Template router → `list_templates`, `select_template` tools
- Project ledger → `project_status`, `cost_report` tools
- Probe → `probe_media` tool

### A4. **HIGH — In-memory job queue with no persistent backend**

`InMemoryJobQueue` is the only queue implementation. The codebase warns users
about this at runtime (`_warn_in_memory_queue_once`), but there is no
production-ready alternative. Jobs are lost on process exit.

**Fix:** Add a SQLite-backed `PersistentJobQueue` implementation of the
`JobQueue` ABC. The project ledger already uses SQLite — reuse the same
connection pattern.

### A5. **HIGH — No progress streaming or real-time observability**

Phase F is explicitly planned but not started. Long renders (music generation,
video generation) block with no feedback. Users polling `ve project-status`
get no insight into what's happening right now.

**Fix:**
- Add SSE/WebSocket endpoint to worker for progress events
- Emit structured progress events from every pipeline stage
- Build a lightweight `ve watch <job-id>` command that tails progress
- Surface progress in the MCP server as streaming tool results

### A6. **MEDIUM — Skills are separate packages but tightly coupled to CLI**

Skills live in `skills/` as independent packages, but they import directly
from `video_editor_ffmpeg`, `video_editor_state`, and each other with no
formal interface boundaries. The skill package structure suggests independence
that doesn't exist in practice.

**Fix:** Define formal `SkillProtocol` with `run(ctx, **kwargs) -> dict`
signature. Have each skill implement it. The pipeline and worker dispatch
through the protocol, not direct imports.

### A7. **MEDIUM — No plugin/extension system for providers**

Adding a new provider requires:
1. Writing the provider class in the right subdirectory
2. Registering it in `providers/__init__.py`
3. Adding config to `config.yaml`
4. Adding scoring defaults to `scoring.py`
5. Adding pricing to `budget.py`
6. Adding concurrency limits to `manager.py`

This is 6 touch points for one provider. It should be 1–2.

**Fix:** Use Python entry points (`pyproject.toml` `[project.entry-points]`)
for provider discovery. A new provider package just needs to declare its
entry point and the registry auto-discovers it.

### A8. **MEDIUM — Remotion/Node renderer has zero JS tests**

`apps/editor` and `apps/renderer` are optional but have no test coverage.
The TypeScript types in `packages/remotion-types` are untested.

**Fix:** Add at least smoke tests for:
- Remotion compositions render without crashing
- ScenePlan → Remotion props round-trip
- FableCut project.json → Remotion scene mapping

### A9. **LOW — Duplicate REPO_ROOT resolution**

`REPO_ROOT` is computed in both `main.py` (line 135) and `pipeline.py`
(line 56) with identical `Path(__file__).resolve().parents[4]` logic.
If the directory depth ever changes, both break.

**Fix:** Define `REPO_ROOT` once in a shared constants module.

### A10. **LOW — Config resolution is scattered**

`ProjectConfig.load()` is called from multiple places with different
fallback logic. The `_resolve_presets_dir` helper in `main.py` duplicates
config-loading logic that should live in the config package.

**Fix:** Centralize config resolution in `packages/config`. Add a
`resolve_effective_config()` that merges CLI flags, env vars, and
config.yaml in one place.

## 2. Bugs & Defects

### B1. **HIGH — TTSRouter excludes Kokoro from language-based routing**

`tts_router.py:_pick_provider()` only routes to Kokoro via explicit
`kokoro:` voice prefix. The language-based routing (Sarvam for Indian
languages, ElevenLabs otherwise) never selects Kokoro, even though
Kokoro supports 8+ languages and is the only free/local option.

**Impact:** Users who configure `defaults.tts: tts_router` and expect
Kokoro to be used when no API keys are available will silently get
ElevenLabs errors instead.

**Fix:** Add Kokoro to the language routing table. When no API key is
available for ElevenLabs/Sarvam, fall back to Kokoro automatically.

### B2. **MEDIUM — Budget governor pricing is hardcoded and will drift**

`budget.py:DEFAULT_PRICING` contains hardcoded credit costs per provider.
Real API pricing changes over time (new models, price cuts, provider
changes). The hardcoded values will become inaccurate.

**Fix:** Move pricing to `config.yaml` under each provider's config block.
Allow providers to report actual cost after generation via a
`report_cost()` callback. Keep hardcoded values only as fallback defaults.

### B3. **MEDIUM — No validation that config.yaml provider names are registered**

If a user types `defaults.image: poyo_ai` but the provider registry key
is `poyo_ai` (matching), it works. If they type `poyo-ai` (hyphen), it
silently fails because the registry lookup returns the stub provider.

**Fix:** Add a `config validate` command that cross-references
`config.yaml` provider names against the registry and reports mismatches.
Run this validation at engine startup with a warning.

### B4. **MEDIUM — Asset cache has no TTL or eviction policy**

`AssetIngestionManager` caches generated assets in `.cache/assets/` with
content-addressed keys, but never expires or evicts them. Over time, the
cache grows unboundedly.

**Fix:** Add:
- Configurable `asset_cache_max_age_days` (default 30)
- Configurable `asset_cache_max_size_gb` (default 10)
- `ve cache-prune` command
- Automatic eviction on `ve run` startup

### B5. **MEDIUM — No graceful degradation when optional providers are unavailable**

If `poyo_ai` is configured as the default image provider but the API key
is missing or the service is down, the pipeline fails hard. There's no
automatic fallback to the next-best scored provider.

**Fix:** Extend `ScoredProviderSelector` to return a ranked list, not just
the winner. The manager tries providers in rank order until one succeeds.

### B6. **LOW — 86 mypy `unused-ignore` errors**

All in test files (`test_storyteller_planner.py` has 19, others scattered).
These are harmless at runtime but mask real type errors and add noise.

**Fix:** Run `ruff check --fix` with the `unused-ignore` rule, or manually
remove the stale `# type: ignore` comments.

### B7. **LOW — `_warn_in_memory_queue_once` uses a global mutable flag**

The `_in_memory_warned` global (line 65 of `main.py`) is not thread-safe.
If two threads call `ve enqueue` simultaneously, the warning may fire
twice or not at all.

**Fix:** Use `threading.Lock` or an atomic flag. Better: remove the
warning once a persistent queue backend exists (see A4).

### B8. **LOW — `DEFAULT_MUSIC_PATHS` in pipeline.py hardcodes repo-relative paths**

`pipeline.py` lines 58–62 hardcode `assets/music/default.{mp3,wav,m4a}`
relative to `REPO_ROOT`. If the engine is installed as a package (not run
from the repo), these paths won't exist.

**Fix:** Read the default music path from `config.yaml`'s
`audio.default_music_path`, which already exists. Remove the hardcoded
fallback list.

### B9. **LOW — `ModelName` enum in `llm/router.py` is stale**

`ModelName` (line 25–31) hardcodes model names like `kimi-k2.6:cloud`
and `qwen3.6:cloud`, but `config.yaml` now uses `minimax-m3:cloud` and
`qwen3-coder-next:cloud`. The enum is only used as fallback defaults in
`TASK_MODELS` (line 59), but those defaults are overridden by config.yaml
anyway. The stale names are confusing.

**Fix:** Either remove the enum (config.yaml is the source of truth) or
update it to match the current config.yaml defaults.

### B10. **LOW — `_require_job` checks for `ingest/manifest.json` but v2 skills don't use ingest**

The `_require_job()` function (line 73) checks for `ingest/manifest.json`,
which only exists for the legacy v1 raw-footage pipeline. v2 skills
(`rough_cut`, `graphics`, etc.) use `work/{job_id}/manifest.json`.

**Fix:** Check for `manifest.json` at the job work root, not the ingest
subdirectory. Or remove the check entirely — the manifest is created
on first access anyway.

## 3. Code Quality & Maintainability

### C1. **HIGH — No integration/E2E tests for the full `ve run` path**

`test_engine_integration.py` tests handshake contracts (worker dispatch,
pipeline stage progression, manifest resume) but doesn't actually run a
full `ve run` with real FFmpeg. The E2E smoke tests in
`test_storyteller_e2e_smoke.py` mock everything.

**Fix:** Add at least one true E2E test that:
1. Creates a synthetic test video with `testsrc`
2. Runs `ve run` through the full skills pipeline
3. Asserts `final.mp4` exists, has correct duration, and is playable

### C2. **MEDIUM — No performance benchmarks or regression tests**

There are no tests that assert render time, memory usage, or cache hit
rates. Performance regressions are invisible.

**Fix:** Add a `tests/bench/` directory with:
- Cache hit rate benchmarks
- Pipeline stage timing benchmarks
- Memory usage ceilings for large jobs

### C3. **MEDIUM — Inconsistent error handling patterns**

Some functions raise custom typed exceptions (`JobNotFoundError`,
`BudgetExceededError`), others raise generic `RuntimeError` or
`ValueError`, and some just `return None` on failure. Callers can't
rely on a consistent error-handling contract.

**Fix:** Define a `VEError` base class and have all engine exceptions
inherit from it. Document the error hierarchy in `ARCHITECTURE.md`.

### C4. **MEDIUM — Logging is inconsistent**

Some modules use `structlog`, others use `print()`, and some use
`typer.echo()`. The worker uses `structlog` but the CLI commands
use `typer.echo()` for user-facing output and `structlog` for debug.
There's no clear separation between user-facing output and debug logs.

**Fix:** Adopt a convention:
- `logger.info()` → operational events (stage start/complete, asset generated)
- `logger.debug()` → detailed diagnostics
- `typer.echo()` / `rich.console` → user-facing CLI output only
- Never `print()` in library code

### C5. **LOW — Docstring coverage is uneven**

Core packages (`ffmpeg`, `state`, `asset_ingestion`) have good docstrings.
Skills and CLI commands have minimal or no docstrings. The `main.py`
worker handlers have no docstrings at all.

**Fix:** Add docstrings to all public functions in `skills/` and
`apps/cli/`. Enforce with `ruff` rule `D103` (require docstrings for
public functions) in `pyproject.toml`.

### C6. **LOW — `pyproject.toml` has no `[project.scripts]` entry points**

The CLI is invoked via `uv run ve`, which works but is non-standard.
There's no `ve` console script registered.

**Fix:** Add to `pyproject.toml`:
```toml
[project.scripts]
ve = "video_editor_cli.main:app"
```

## 4. Provider Gaps & Integration Opportunities

### D1. **HIGH — ACE-Step 1.5 music provider not integrated**

ACE-Step 1.5 is MIT-licensed, runs on 4GB VRAM (or CPU), generates music
in <10s on a consumer GPU, supports 50+ languages, and has a free API at
acemusic.ai. It's the strongest free music generation option available.

**Integration plan:**
- Add `ace_step` provider to `providers/audio/`
- Register in config.yaml under `assets.providers`
- Add to scoring defaults and budget pricing
- Wire into `MusicProvider` protocol

### D2. **HIGH — Additional free TTS providers not integrated**

The engine has Kokoro (82M params, CPU-friendly) but is missing:
- **KittenTTS** (15M params, 25MB on disk, Apache 2.0) — smallest possible TTS
- **MOSS-TTS-Nano** (0.1B, CPU-only, 20 languages, voice cloning) — best CPU option
- **Qwen3-TTS** (0.6B/1.7B, Apache 2.0, 10 languages, voice design) — best quality

**Integration plan:**
- Add `kitten_tts`, `moss_tts`, `qwen3_tts` providers
- Add to TTSRouter language routing table
- Prioritize in free_mode config profile

### D3. **HIGH — OpenRouter media generation provider not wired**

`.mcp.json` has the OpenRouter MCP server configured, and
`OPENROUTER_API_KEY` is in `.env.example`. But there's no
`openrouter` provider in the asset ingestion system. OpenRouter
offers free/lowest-priced image, video, and audio generation
models through a single API.

**Integration plan:**
- Add `openrouter` provider implementing `GenerativeProvider`
- Support image, video, and TTS task types
- Use the OpenRouter MCP server for live model discovery
- Add to scoring defaults with competitive pricing

### D4. **MEDIUM — Additional stock footage APIs not integrated**

Only Pexels is integrated. Missing:
- **Coverr** — free API, cinematic non-stock-looking clips
- **Mixkit** — no API key required, HD video
- **NASA Image & Video Library** — public domain, no key required
- **Pixabay** — 2M+ videos, higher rate limits than Pexels
- **stockmedia-sdk** — unified Python SDK for Pexels + Pixabay

**Integration plan:**
- Add `coverr`, `mixkit`, `nasa`, `pixabay` providers
- Or integrate `stockmedia-sdk` as a single multi-source provider
- Add to scoring with cost=0.0 (free tier)

### D5. **MEDIUM — NovAI cogvideox-flash ($0/video generation) not integrated**

NovAI offers `cogvideox-flash` for $0/generation through an
OpenAI-compatible API. No credit card required. Good for prototyping
and CI pipelines.

**Integration plan:**
- Add `novai` provider implementing `GenerativeProvider` for video
- Use OpenAI-compatible client (same pattern as existing providers)
- Add to scoring with cost=0.0

### D6. **MEDIUM — No free_mode config profile**

The `../tool-lab/research/2026-07-12-free-tools-survey.md` document proposes a
`free_mode` config profile that routes everything through free providers
(Piper/Kokoro TTS, Pexels/Wikimedia stock, skip generative video). This
was identified as a valuable feature but never implemented.

**Fix:** Add a `config.free.yaml` profile:
```yaml
assets:
  defaults:
    tts: kokoro_tts
    image: pexels
    video: pexels
    music: ace_step
    sfx: stub_sfx
```

### D7. **LOW — Demucs audio isolation not integrated**

`../tool-lab/research/2026-07-12-free-tools-survey.md` identifies Demucs (Meta's
free stem separator) as a free alternative to ElevenLabs isolation.
It's not integrated.

**Fix:** Add `demucs` provider to `providers/audio/`.

### D8. **LOW — Piper TTS not integrated**

Piper TTS was identified as a free local TTS option but Kokoro was
chosen instead. Piper is still valuable for ultra-low-resource scenarios
(runs on Raspberry Pi).

**Fix:** Add `piper_tts` provider for completeness in the free_mode profile.

## 5. New Tools & Features from Internet Research

### E1. **MCP Server ecosystem has matured significantly**

The 2026 landscape shows MCP servers as the standard integration shape
for AI video tools:

| Tool | Tools | License | Key Feature |
|------|-------|---------|-------------|
| **Kinocut** | 150 | Apache 2.0 | Governed editing, C2PA provenance, Video Receipts |
| **NIRA Video MCP** | 55 | MIT/$49 PRO | 6 AI video gen models, 16 platform presets |
| **video-creator-mcp** | 31 | Free | Agent-driven content creation from prompts |
| **CutAI** | MCP server | MIT | Natural-language editing, Edit Style Transfer |

**Recommendation:** Build our MCP server (see A3) following Kinocut's
tool granularity pattern — one tool per atomic operation, typed inputs,
structured outputs.

### E2. **Browser-based editing is now viable**

**Timeline Studio** (`MartinDelophy/ai-video-editor`, MIT, 301 stars) runs
entirely in the browser with ONNX/WebGPU: Kokoro TTS, Whisper captions,
Stable Audio 3 music, YOLOS+MODNet smart framing, JoyVASA talking avatars.
It's PWA-installable and fully offline.

**Vlo** (`PxTicks/vlo`, AGPL-3.0) is a ComfyUI-backed timeline editor
with SAM2 masking, video inpainting, keyframe+spline editor, and
text-to-video generation.

**Recommendation:** Evaluate Timeline Studio's ONNX-in-browser approach
for a potential zero-install preview mode. Its Kokoro + Whisper + Stable
Audio pipeline is a subset of what we already do server-side.

### E3. **AI-native NLEs are emerging**

**AI Video Editor** (`tjameswilliams/ai-video-editor`, MIT) uses
Remotion 4 + React 19 for motion graphics with LLM-authored custom
TSX components on demand. It has an MCP server with 50+ tools and
supports any OpenAI-compatible LLM.

**OpenCut AI** (`Ekaanth/OpenCut-AI`, MIT, 167 stars) is a full
CapCut/Descript replacement with edit-by-text, voice cloning, AI
music, 9 video gen models, and Docker deployment.

**Recommendation:** Study AI Video Editor's "LLM-authored custom
components" pattern — having the LLM write new Remotion TSX infographics
on demand is a capability we could add to our engine's graphics skill.

### E4. **Music generation has advanced dramatically**

| Model | License | Min VRAM | Free API | Quality |
|-------|---------|----------|----------|---------|
| **ACE-Step 1.5** | MIT | 4GB | ✅ acemusic.ai | Between Suno v4.5–v5 |
| **HeartMuLa 3B** | Apache 2.0 | Medium | HuggingFace Demo | Near Suno-level |
| **SongGeneration v2** | Custom | 10GB | HuggingFace Space | PER 8.55% (beats Suno v5) |
| **Muse** | MIT | Medium | None | ACL 2026 paper |

**Recommendation:** Integrate ACE-Step 1.5 first (MIT, lowest barrier).
Add HeartMuLa as a higher-quality option for users with more VRAM.

### E5. **TTS has commoditized with excellent free options**

| Model | Size | CPU? | Languages | Voice Clone |
|-------|------|------|-----------|-------------|
| **KittenTTS** | 15M | ✅ | 8 voices | ❌ |
| **MOSS-TTS-Nano** | 0.1B | ✅ | 20 | ✅ |
| **Kokoro-82M** | 82M | ✅ | 8 | ❌ |
| **Qwen3-TTS 0.6B** | 0.6B | GPU | 10 | ✅ |
| **Qwen3-TTS 1.7B** | 1.7B | GPU | 10 | ✅ + Voice Design |

**Recommendation:** Add KittenTTS (smallest) and MOSS-TTS-Nano (best
CPU option with cloning) to the TTSRouter. Qwen3-TTS 1.7B is the best
quality option but requires GPU.

### E6. **Multi-source stock media aggregation is solved**

**stockmedia-sdk** (Python, PyPI) wraps Pexels + Pixabay in a single
well-typed SDK with auto-pagination, rate-limit tracking, and retry logic.

**refkit** (TypeScript, 18+ providers) normalizes licenses across sources
and includes an MCP adapter.

**web-media-getter** (Python, stdlib only) fans out one query across 9
sources including Openverse, Wikimedia, Internet Archive, Library of
Congress, and NASA.

**Recommendation:** Integrate `stockmedia-sdk` as a `stockmedia` provider
that wraps Pexels + Pixabay in one call. Add `web-media-getter` as a
`free_stock` provider for the free_mode profile.

## 6. Testing Gaps

### T1. **HIGH — No true end-to-end render test**

All pipeline tests mock FFmpeg, mock providers, or use synthetic data.
There's no test that actually runs FFmpeg and produces a playable MP4.

**Fix:** Add `tests/test_e2e_render.py` with:
- `test_full_skills_pipeline_produces_playable_mp4`
- `test_music_video_pipeline_produces_playable_mp4`
- `test_storyteller_pipeline_produces_playable_mp4`

Use `testsrc` + `sine` filters for synthetic input, assert output is
playable via `ffprobe`.

### T2. **HIGH — No provider integration tests against real APIs**

Provider tests mock HTTP responses. There are no tests that actually
call Pexels, PoYo, ElevenLabs, or any other real API. Provider
breakage is only discovered at runtime.

**Fix:** Add `tests/test_provider_live.py` (skipped by default, gated
on `RUN_LIVE_TESTS=1` env var) that makes real API calls and asserts
valid responses.

### T3. **MEDIUM — No concurrency/race condition tests**

The asset manager uses `asyncio` with per-provider semaphore limits
and a circuit breaker. There are no tests for:
- Concurrent requests to the same provider respecting the semaphore
- Circuit breaker opening/closing under concurrent load
- Cache race conditions (two requests for the same asset simultaneously)

**Fix:** Add `tests/test_concurrency.py` with `asyncio`-based race tests.

### T4. **MEDIUM — No tests for error recovery paths**

The worker loop catches exceptions and calls `queue.fail()`, but there
are no tests verifying that:
- A failed stage doesn't corrupt the manifest
- A failed asset generation doesn't block other assets
- A circuit-breaker trip recovers after the cooldown period

**Fix:** Add error-path tests in `tests/test_pipeline_error_paths.py`
(expand existing file).

### T5. **LOW — No tests for the project ledger's SQLite schema migrations**

The ledger schema is created with `CREATE TABLE IF NOT EXISTS`. If the
schema changes, old databases will fail silently or with cryptic errors.

**Fix:** Add schema versioning and migration tests.

### T6. **LOW — No performance regression tests**

See C2.

## 7. Security & Robustness

### S1. **MEDIUM — API keys loaded from `.env` with no validation**

`_load_dotenv()` loads `.env` at import time. If the file is missing
or a key is empty, providers fail at runtime with cryptic errors.
There's no startup check that required keys are present.

**Fix:** Add a `ve check-config` command that:
- Loads config.yaml
- Resolves all `api_key_env` references
- Reports which keys are missing
- Suggests which providers are usable with current keys

### S2. **MEDIUM — No input sanitization on user-provided paths in worker payloads**

Worker payloads accept `work_root` and `output_root` as strings. A
malicious payload could write outside the intended directory.

**Fix:** Validate that resolved paths are within an allowed base
directory. Reject payloads with `..` traversal.

### S3. **LOW — No rate limiting on the worker loop**

`ve worker --max-jobs N` processes N jobs then exits, but there's no
per-second or per-minute rate limit. A flood of enqueued jobs could
overwhelm API providers.

**Fix:** Add `--max-jobs-per-minute` flag to worker. Default to a
conservative value (e.g., 10).

### S4. **LOW — FFmpeg subprocess calls don't set resource limits**

`run_ffmpeg()` in `packages/ffmpeg/run.py` spawns FFmpeg subprocesses
with no CPU or memory limits. A runaway FFmpeg process (e.g., on a
corrupted input) could exhaust system resources.

**Fix:** Use `resource.setrlimit()` or `subprocess.Popen(preexec_fn=...)`
to set CPU time and memory limits on FFmpeg child processes.

### S5. **LOW — No C2PA provenance or content authenticity**

Kinocut has C2PA provenance and Video Receipts. Our engine produces
no content authenticity metadata.

**Fix:** Add optional C2PA signing to the export stage. At minimum,
embed metadata in the output MP4 with the job ID, timestamp, and
pipeline hash.
