## Findings

### CRITICAL

#### #165 — `ProjectConfig.resolve_path` does not contain configured paths to the repo root
- **File:** `packages/config/src/video_editor_config/__init__.py` (resolve_path)
- **Region:** `resolve_path` implementation
- **Description:** `resolve_path` returns absolute paths unchanged and joins repo-relative paths without normalizing or containing them under `repo_root`. A config value such as `paths.presets: /etc`, `audio.default_music_path: /etc/passwd`, or `paths.presets: ../../etc` resolves outside the repository and is passed to `GraphicsSkill`/`MusicSkill`, enabling arbitrary file reads.
- **Repro:** Set `paths.presets: /etc` in `config.yaml` and run a command that loads presets; `GraphicsSkill` reads files from `/etc`.

#### #166 — `render.cache_dir` can escape the job work directory
- **File:** `apps/cli/src/video_editor_cli/pipeline.py`
- **Region:** `124-128, 164-168`
- **Description:** `SkillsPipeline` passes `project_config.render.cache_dir` directly to `AssetIngestionManager(cache_dir=...)`. If the configured value is absolute or contains `..`, the asset cache is written outside the job work directory, allowing cross-tenant cache poisoning or arbitrary file reads on shared workers.
- **Repro:** Set `render.cache_dir: /tmp/cache` in `config.yaml` and run `ve run`; `AssetIngestionManager` writes its asset cache to `/tmp/cache` instead of `<work_dir>/.cache`.

### HIGH

#### #167 — `render.output_name_template` path traversal can write final export outside `output_dir`
- **File:** `apps/cli/src/video_editor_cli/pipeline.py`
- **Region:** `367-373`
- **Description:** `SkillsPipeline` builds the export filename by replacing `{stage}` with `final` in `project_config.render.output_name_template` and then joins it with `ctx.output_dir`. A template containing `../` or directory separators resolves outside `output_dir`, allowing the final deliverable to be written to an unintended location.
- **Repro:** Set `render.output_name_template: ../../{stage}_outside.mp4` and run `ve run`; `ExportSkill` writes the final video to the parent of `ctx.output_dir`.

#### #168 — Missing `--config` file silently falls back to defaults
- **File:** `packages/config/src/video_editor_config/__init__.py`
- **Region:** `217-231`
- **Description:** `ProjectConfig._resolve_path` checks `candidate.exists()` and returns `None` for any non-existent path. `ProjectConfig.load` then returns a fully default config with no warning or error. A typo in `--config` means the engine runs with default providers, credentials, and paths instead of the intended project config.
- **Repro:** Run `ProjectConfig.load('/tmp/this_does_not_exist.yaml')`; it returns a default `ProjectConfig` without raising or logging.

#### #169 — Worker asset handlers load `config_path` without path containment guard
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `1816, 1841, 1941, 1979, 2026`
- **Description:** `_handle_music_generate`, `_handle_sfx_generate`, `_handle_align`, `_handle_audio_isolate`, and `_handle_speech_to_speech` read `payload['config_path']` directly and pass it to `AssetProviderConfig.load(Path(...))`. They do not route it through `_resolve_payload_path`, unlike `_handle_run` and the audio path fields. A malicious queue payload can supply an absolute `config_path` outside the job's work/output directories and read arbitrary YAML files on the worker.
- **Repro:** Enqueue `music_generate` with payload `{'config_path': '/etc/passwd', ...}`; the handler will call `yaml.safe_load` on `/etc/passwd`. The same payload key in `run` is guarded.

#### #170 — CLI `output_name` is not sanitized, allowing path traversal out of `<work>/audio/`
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `1306-1309, 1355-1358`
- **Description:** The `audio_isolate` and `speech_to_speech` Typer commands join the user-supplied `--output-name` directly with `ctx.work_dir / 'audio'`. They never call `_safe_filename()`, so a value like `../../../tmp/pwned.mp3` escapes the intended output directory and can overwrite arbitrary files. The worker handlers do call `_safe_filename()` for the same field, so the sync CLI bypasses that guard.
- **Repro:** `ve audio-isolate job --audio input.mp3 --output-name '../../../tmp/pwned.mp3'` writes to `/tmp/pwned.mp3` instead of the job's `audio/` directory.

#### #171 — Empty `audio/*` response is accepted and written to disk
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/_media.py`
- **Region:** `46-68`
- **Description:** `save_audio_response` trusts any `Content-Type` beginning with `audio/` and writes `response.content` even when it is empty. A `/v1/audio-isolation` or `/v1/speech-to-speech` response with `Content-Type: audio/mpeg` and an empty body creates a zero-byte file. The failure surfaces later at `probe_media` with a confusing ffprobe error instead of a clear "empty audio response" error.
- **Repro:** Mock the endpoint to return `httpx.Response(200, headers={'content-type': 'audio/mpeg'}, content=b'')` and call `ElevenLabsIsolationProvider.generate()`; `output_path` is created with 0 bytes and `probe_media` raises.

#### #172 — Audio responses with `application/octet-stream` Content-Type are rejected
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/_media.py`
- **Region:** `19-23`
- **Description:** `_is_audio_content()` returns `False` whenever a `Content-Type` header is present but does not start with `audio/`. If a server, CDN, or proxy returns a valid MP3/WAV body with `Content-Type: application/octet-stream`, `save_audio_response()` raises `MediaContentError` even though the byte signature is correct. The sniffing fallback only runs when the header is completely absent, so a present but generic content type defeats validation.
- **Repro:** Create `httpx.Response(200, content=valid_mp3_bytes, headers={'content-type': 'application/octet-stream'})` and call `save_audio_response(response, 'out.mp3')`; it raises `MediaContentError`.

### MEDIUM

#### #173 — Unknown keys in `llm:` and `assets:` sections silently dropped when loaded via `ProjectConfig`
- **File:** `packages/config/src/video_editor_config/__init__.py`
- **Region:** `131-172, 174-187`
- **Description:** `ProjectConfig._load_llm_section` and `_load_assets_section` call `model_validate` directly on the section. They bypass `LLMConfig._warn_unknown_keys` and `AssetProviderConfig._warn_unknown_keys`, so misspelled provider names or stray options (e.g. `llm: {providors: ...}` or `assets: {fal: ...}`) are silently ignored instead of producing warnings.
- **Repro:** Load a config with `llm: {providors: {...}}` or `assets: {fal: {...}}` through `ProjectConfig.load()`; the keys disappear without warnings. Loading the same file directly through `LLMConfig.load()` or `AssetProviderConfig.load()` would warn.

#### #174 — Provider `base_url` and `provider_options` lack URL/SSRF validation
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/visual/fal_ai.py`
- **Region:** `61-97`
- **Description:** `FalAIProvider` reads `base_url` and `provider_options.status_url/video_model/poll_*` directly from config and passes them to `httpx` without validating scheme or host. A malicious config can redirect cloud provider traffic to an internal/metadata endpoint, creating an SSRF vector in multi-tenant jobs. The same pattern exists in the ElevenLabs providers, which also read a configurable `base_url`.
- **Repro:** Set `assets.providers.fal_ai.base_url: http://169.254.169.254/latest/` in `config.yaml`; the provider attempts to call the cloud metadata endpoint.

#### #175 — `audio-isolate` CLI and worker ignore output extension and `file_format`
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `1297-1313, 1979-1990`
- **Description:** Both `ve audio-isolate` and `_handle_audio_isolate` call `isolation_request()` with the hardcoded defaults `output_ext='mp3'` and `file_format='other'`, ignoring the user-supplied `--output-name` extension and never exposing a `--file-format` option. A user requesting `--output-name isolated.wav` receives MP3 bytes written to a `.wav` file, and users cannot request `pcm_s16le_16` output through the CLI or worker.
- **Repro:** Run `ve audio-isolate job --audio in.mp3 --output-name out.wav` and inspect the output; ffprobe reports MPEG audio inside a `.wav` container.

#### #176 — Stub speech-to-speech pitch shift treats semitones as a raw pitch ratio
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/audio/stub.py`
- **Region:** `190-206`
- **Description:** The parameter is named `shift_semitones` but the filter string is `rubberband=pitch={shift}`. FFmpeg's rubberband `pitch` option expects a scale factor (`1.0` = no change), not a semitone count, so `shift_semitones=2` shifts one octave up instead of two semitones. The output also always re-encodes to `libmp3lame` regardless of the requested `output_ext`.
- **Repro:** Create a request with `params['shift_semitones']=2` and compare pitch; the result is ~12 semitones higher than expected, and the file is MP3 even when `output_ext` is `'wav'`.

#### #177 — Speech-to-speech provider and request builder ignore `config.yaml` defaults
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/audio/elevenlabs_speech_to_speech.py`
- **Region:** `79-86, 95-96`
- **Description:** `ElevenLabsSpeechToSpeechProvider.__init__` stores `ProviderConfig` but `generate()` never reads `self.config.default_model` or `self.config.default_voice`; it falls back to module-level `DEFAULT_MODEL_ID` and requires `voice_id` in `request.params/prompt`. At the same time, `speech_to_speech_request()` hardcodes `model_id='eleven_english_sts_v2'` and never consults `AssetProviderConfig`. Operators who set `default_model`/`default_voice` in `config.yaml` see no effect.
- **Repro:** Set `assets.providers.elevenlabs_speech_to_speech.default_model` and `default_voice` in `config.yaml`; both `ve speech-to-speech` and the worker still use `eleven_english_sts_v2` and the CLI-provided `voice_id`.

#### #178 — Speech-to-speech output file extension can mismatch the returned audio format
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/audio/elevenlabs_speech_to_speech.py`
- **Region:** `125`
- **Description:** The provider writes whatever raw bytes ElevenLabs returns to `output_path`, whose extension comes from `request.output_ext`. If `output_ext='wav'` but `output_format` remains the default `'mp3_44100_128'`, the file is MP3 data named `.wav`. `save_audio_response()` validates that the body is audio but does not validate that it matches the extension, so downstream FFmpeg stages may mis-parse or fail format-specific operations.
- **Repro:** Build an `AssetRequest` with `output_ext='wav'` and params `output_format='mp3_44100_128'`, mock the endpoint to return MP3 bytes, and call `provider.generate()`; `out.wav` contains ID3/0xfffb MP3 headers.

#### #179 — Stub speech-to-speech provider ignores requested output extension
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/audio/stub.py`
- **Region:** `190-208`
- **Description:** In pitch-shift mode the stub hardcodes `-c:a libmp3lame`. In copy mode it writes the input bytes unchanged. Both paths produce a file whose extension is taken from `output_path`, so a request with `output_ext='wav'` yields MP3 data saved as `.wav`. This makes the stub an unreliable stand-in for non-MP3 output-format tests.
- **Repro:** Create an `AssetRequest` with `output_ext='wav'` and params `audio_path=<mp3>, shift_semitones=2`; the resulting `out.wav` starts with MP3 ID3/0xfffb bytes, not RIFF.

#### #180 — Speech-to-speech CLI and worker payload omit documented options
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `286-295, 1317-1362`
- **Description:** The `_SpeechToSpeechPayload` schema and the `speech_to_speech` Typer command accept `--output-name` but have no `--output-format`, `--output-ext`, or `--seed` options, and do not auto-assemble `voice_settings` from `stability/similarity_boost/style/use_speaker_boost`. Users can only get the ElevenLabs default `mp3_44100_128` output written to a `.mp3` file; there is no supported way to request `pcm_16000`, `wav`, deterministic `seed`, or per-voice tuning through `ve speech-to-speech` or `ve enqueue speech_to_speech`.
- **Repro:** Inspect `_PAYLOAD_SCHEMAS['speech_to_speech']` and the `speech_to_speech` Typer command; neither contains `output_format`, `output_ext`, `seed`, nor the individual voice tuning keys.

#### #181 — `audio-isolate` and `speech-to-speech` `--audio` options are typed as `str`
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `1274, 1319`
- **Description:** The `--audio` parameter in both commands is declared as `str` and only converted to `Path` inside the function. Typer performs no path normalization, tilde expansion, or path-type validation at the option layer. This is inconsistent with other commands and can cause confusing "Audio file not found" errors for paths like `~/input.mp3`.
- **Repro:** `ve audio-isolate job --audio '~/music/input.mp3'` fails the existence check because `~` is not expanded, even when the file exists.

#### #182 — Worker audio handlers accept a directory as the audio source
- **File:** `apps/cli/src/video_editor_cli/main.py`
- **Region:** `1971-1977, 2018-2024`
- **Description:** After `_resolve_payload_path` confirms the audio path is inside the allowed roots, `_handle_audio_isolate` and `_handle_speech_to_speech` only check `.exists()`. A directory passes this test and is then handed to `AssetIngestionManager`, which fails later with a less clear error when the provider tries to open it as a file. They should explicitly reject directories with `is_dir()`, mirroring `_handle_brief`.
- **Repro:** Enqueue `audio_isolate` with `audio` pointing to an existing directory inside the job work dir; the job fails inside `manager.resolve` rather than with a clear validation error.

#### #183 — Missing worker path-traversal regression tests for new audio handlers
- **File:** `tests/test_cli.py`
- **Region:** `1569-1707, 1709-1851`
- **Description:** `TestAlignCli` has `test_align_handler_rejects_audio_outside_work_root` and `TestAudioCli` has a similar voiceover test, but neither `TestAudioIsolateCli` nor `TestSpeechToSpeechCli` includes a regression test that an audio path outside the allowed work/output roots is rejected by `_resolve_payload_path`. The guard code is present, so this is a coverage gap that could regress silently.
- **Repro:** Add tests analogous to `test_align_handler_rejects_audio_outside_work_root` for `audio_isolate` and `speech_to_speech` payloads.

#### #184 — Missing path-traversal regression tests for new ElevenLabs audio providers
- **File:** `tests/test_elevenlabs_isolation.py`
- **Region:** `59-91, 109-129`
- **Description:** `ElevenLabsIsolationProvider` and `ElevenLabsSpeechToSpeechProvider` read `params['audio_path']` directly, but the regression suites only test happy path and missing-param cases. Unlike `test_cli.py` (run/rough_cut/align), there is no test that feeds a path outside the job directory and asserts clear rejection.
- **Repro:** Add tests with `params['audio_path']=str(tmp_path.parent / 'outside.mp3')` for both providers and assert `ValueError`/`FileNotFoundError`.

#### #185 — Missing input-file-not-found error path tests for new ElevenLabs audio providers
- **File:** `tests/test_elevenlabs_isolation.py`
- **Region:** `109-129`
- **Description:** Only the absence of the `audio_path` key is tested for the isolation and speech-to-speech providers. A real failure mode is a present `audio_path` pointing to a deleted or moved file. The forced-alignment suite already covers this pattern (`test_elevenlabs_alignment_audio_file_not_found`).
- **Repro:** Add tests where `params['audio_path']=str(tmp_path / 'no_such_file.mp3')` for both providers and assert a clear `FileNotFoundError` or provider-specific error.

#### #186 — Tests leak environment changes via unmanaged `pytest.MonkeyPatch` instances
- **File:** `tests/test_elevenlabs_isolation.py`
- **Region:** `112`
- **Description:** `test_elevenlabs_isolation_missing_audio_path` and `test_elevenlabs_speech_to_speech_missing_voice_id` create `pytest.MonkeyPatch()` directly and call `setenv` without the fixture or a context manager, so the `ELEVENLABS_API_KEY` environment change is not torn down. This can pollute later tests and mask missing-key failures.
- **Repro:** Replace local `MonkeyPatch()` instances with the `pytest monkeypatch` fixture or use `with pytest.MonkeyPatch() as mp: ...` context manager.

#### #187 — No end-to-end CLI regression test that config defaults are applied
- **File:** `tests/test_cli.py`
- **Region:** `365, 1494-1565`
- **Description:** `test_project_config.py` verifies `SkillsPipeline` reads `presets_dir`/`default_music_path`/`render` template from config, and `test_pipeline.py` checks `config_path` forwarding. However, `test_cli.py` never invokes `ve run --config <yaml>` and asserts a configured default actually affects the output, leaving the CLI default-application path unguarded.
- **Repro:** Add a CLI test that writes a `config.yaml` with custom `paths.presets` and `audio.default_music_path`, runs `ve run --config`, and asserts the final video uses the configured assets.

### LOW

#### #188 — `RenderConfig` codec/bitrate/fps settings are loaded but not consumed
- **File:** `packages/config/src/video_editor_config/__init__.py`
- **Region:** `48-70`
- **Description:** `RenderConfig` declares `video_codec`, `audio_codec`, `crf`, `video_bitrate`, `audio_bitrate`, `fps`, `width`, and `height`, but no current skill reads them. FFmpeg helpers in `packages/ffmpeg` hardcode `libx264/aac/192k/23`, so a user changing `render.video_codec` to `libx265` or `render.audio_bitrate` to `320k` is silently ignored.
- **Repro:** Set `render.video_codec: libx265` and `render.audio_bitrate: 320k`; observe generated ffmpeg commands still use `libx264` and `192k`.

#### #189 — `render.hyperframes` section is silently dropped
- **File:** `packages/config/src/video_editor_config/__init__.py`
- **Region:** `124-125`
- **Description:** The committed `config.yaml` contains a `render.hyperframes` mapping with `cli` and `timeout` keys, but `RenderConfig` has no `hyperframes` field and `ProjectConfig.model_validate` ignores extras. As a result, documented config-driven hyperframes CLI/tuning settings have no effect when loaded through `ProjectConfig`.
- **Repro:** Set `render.hyperframes.timeout: 1200` and load `ProjectConfig`; the value is not present on `cfg.render`.

#### #190 — HTTP 4xx/5xx error response bodies are not surfaced
- **File:** `packages/asset_ingestion/src/video_editor_asset_ingestion/providers/audio/elevenlabs_isolation.py`
- **Region:** `89-94`
- **Description:** `response.raise_for_status()` raises `httpx.HTTPStatusError` with only the status code and URL. The provider does not read or include the response body, so an ElevenLabs JSON error detail or HTML outage page is not visible in the propagated exception or manager logs. The same pattern exists in the speech-to-speech provider.
- **Repro:** Mock the endpoint to return 400 with body `{'detail': 'file too large'}`; the resulting `RuntimeError` message shows HTTP 400 but omits the detail text.

## Top recommendations (in priority order)

1. Contain `ProjectConfig.resolve_path` to the repo root so absolute or relative-traversal values for `presets`, `music`, and other configured paths cannot read arbitrary files (#165).
2. Force `render.cache_dir` to be relative to the job work directory (or validate it is contained) so one tenant cannot read or poison another tenant's asset cache (#166).
3. Route `payload['config_path']` in all worker asset handlers through `_resolve_payload_path` so queued jobs cannot read arbitrary YAML files outside the job roots (#169).
4. Sanitize `--output-name` in the sync `audio_isolate` and `speech_to_speech` CLI commands using `_safe_filename()` to prevent writing audio files outside `<work>/audio/` (#170).
5. Validate `render.output_name_template` for path separators/parent references before joining with `ctx.output_dir` so the final export cannot escape the output directory (#167).
