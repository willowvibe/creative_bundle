## 1. Executive Summary

The repository is a local-first AI video-editing engine (Python monorepo + optional Node/Remotion apps) with two primary workflows:

1. **Raw-footage polish** — transcript-first editing with filler/silence removal, jump cuts, captions, b-roll, music, QA, and verification.
2. **Script-to-video generation** — scene-plan-first generation with TTS, generative visuals, motion graphics, music, and multi-aspect exports.

## 2. Critical Findings (Fix Immediately)

### C1. MCP server is type-broken and likely runtime-broken

**Severity:** CRITICAL  
**Files:** `packages/mcp_server/src/video_editor_mcp/tools/*.py`, `packages/mcp_server/src/video_editor_mcp/server.py`

The MCP server carries **79 mypy errors** across 8 files (64 mypy errors total in the repo, the rest are elsewhere). Representative issues:

- `CallToolResult(..., isError=True)` is used everywhere; the correct kwarg is `is_error`.
- `packages/mcp_server/tools/pipeline.py` reuses a single `RoughCutSkill` variable for `GraphicsSkill`, `CaptionsSkill`, `MusicSkill`, `ExportSkill`, etc., and calls methods with wrong signatures.
- `server.py` imports `ServerRequestContext`, which the `mcp` package does not explicitly export.
- `server.py` calls `server.run(read_stream, write_stream)` without required `initialization_options`.

**Impact:** The server compiles but will likely raise `TypeError` or return malformed results when any tool is invoked. It is worse than a stub because it gives the illusion of functionality.

**Action:** Fix mypy errors, add unit tests for every `call_*` function, and add an integration test that spins up the server stdio transport.

### C2. Default provider mismatch breaks `test_config_yaml_models.py`

**Severity:** HIGH  
**File:** `tests/test_config_yaml_models.py`

`config.yaml` now routes tasks through **OpenRouter** models (`anthropic/claude-sonnet-4`, `google/gemini-2.5-flash`). The test hardcodes an Ollama-only "installed" set and fails:

```text
AssertionError: config.yaml references models not in ollama list: {'anthropic/claude-sonnet-4', 'google/gemini-2.5-flash'}
```

**Action:** Update the test to validate against the configured providers in `packages/llm`, or rename it to reflect that it should check provider/model compatibility rather than a static Ollama list.

### C3. Runtime output directories are not ignored

**Severity:** MEDIUM  
**File:** `.gitignore`

`.gitignore` ignores `projects/*/output/`, `projects/*/work/`, `videos/**/work/`, and `output/`, but it does **not** ignore the root-level runtime directories that currently appear as untracked:

- `outputs/`
- `projects/saju-lead-gen/`
- `videos/2026-08-02/`

**Action:** Add `outputs/`, `projects/`, and `videos/` (or the appropriate root patterns) to `.gitignore`, keeping only committed fixture/demo projects under version control.

### C4. `ve update-pricing` does not update pricing

**Severity:** MEDIUM  
**File:** `apps/cli/src/video_editor_cli/commands/update_pricing.py`

The command only rewrites the `last_updated` timestamp in `pricing.yaml`. It does **not** fetch fresh costs from any provider API. This is misleading to users and will silently leave stale prices in place.

**Action:** Either rename the command to `touch-pricing` or implement real fetching from provider APIs (at minimum for OpenRouter, ElevenLabs, FAL, Poyo). Until then, document the limitation clearly.

### C5. Personal voice IDs and provider defaults hardcoded in estimate command

**Severity:** MEDIUM  
**File:** `apps/cli/src/video_editor_cli/commands/estimate.py`

The file contains a comment `"Harish's ElevenLabs voice IDs"` and hardcodes `ATYMJR0SnaN1mSrsnZEi` / `32EwRSV41WufKgzh80Ri`. Default provider/model mappings are also hardcoded instead of coming from `config.yaml` or brand/profile configuration.

**Action:** Move voice IDs and default provider mappings into `config.yaml` / brand profile / `pricing.yaml` and load them at runtime.

### C6. `handlers.py` has a real bug in `storyteller_to_fablecut` call

**Severity:** HIGH  
**File:** `apps/cli/src/video_editor_cli/handlers.py:715`

Mypy reports:

- `Unexpected keyword argument "project_root" for "storyteller_to_fablecut"; did you mean "project_dir"?`
- `Unexpected keyword argument "job_id" for "storyteller_to_fablecut"`
- `Value of type "Coroutine[Any, Any, StorytellerProject]" must be used` (missing `await`)

**Action:** Fix kwargs and add `await`.

### C7. Cost-estimation bug for video duration

**Severity:** MEDIUM  
**File:** `apps/cli/src/video_editor_cli/commands/estimate.py`

In `_tally_costs`, video cost is computed with `total_duration = sum(s.duration_seconds for s in plan.scenes)` for **each** scene request, inflating video cost by the number of scenes. Video should be priced per-second of generated footage per scene, not multiplied by the entire plan duration.

**Action:** Use the per-scene `duration_seconds` for video line items.

## 3. Architecture Gaps

### A1. CLI `main.py` and `handlers.py` remain too large

| File | Lines | Commands / Handlers |
|------|-------|---------------------|
| `apps/cli/src/video_editor_cli/main.py` | 2,807 | ~47 `@app.command` registrations |
| `apps/cli/src/video_editor_cli/handlers.py` | 856 | 15+ worker handlers |
| `apps/cli/src/video_editor_cli/pipeline.py` | 1,116 | `SkillsPipeline`, `MusicVideoPipeline` |
| `tests/test_cli.py` | 3,557 | still a monolith |

The v2 audit recommended splitting `main.py` and `test_cli.py`. While a `commands/` package now exists, the bulk of the CLI surface is still in `main.py`. Typer command definitions, worker dispatch, payload validation, and helper logic are interleaved.

**Action:** Continue the refactor:
- Move every legacy v1 command into `apps/cli/src/video_editor_cli/commands/`.
- Move worker dispatch and payload schemas into `apps/cli/src/video_editor_cli/worker.py` and `payloads.py`.
- Split `tests/test_cli.py` into `tests/cli/test_*.py`.

### A2. MCP server is not a first-class integration

The MCP server is in its own package but is neither tested nor wired into the CI-style checks. There are no tests for tool execution, no integration with the engine, and no documented MCP usage in `README.md` or `docs/CLI_USAGE.md`.

**Action:** Add `tests/test_mcp_server.py`, `tests/test_mcp_integration.py`, and fix the type errors before claiming the server works.

### A3. Dual budget/pricing model (credits + USD)

`packages/asset_ingestion/budget.py` still maintains a legacy `DEFAULT_PRICING` table in abstract "credits" while `pricing.py` exposes USD costs. `BudgetGovernor` accepts either, making cost estimation confusing and error-prone.

**Action:** Deprecate and remove the credit table; standardize on USD via `PricingRegistry`.

### A4. No provider entry-point discovery

Providers are imported by name throughout the codebase. Adding a new provider requires edits in multiple files (`manager.py`, routers, scoring, budget, config validation).

**Action:** Implement plugin-style discovery (e.g., `entry_points` in `pyproject.toml` or a registry that scans a known module prefix).

### A5. Node/Remotion apps are optional and untested

`apps/editor`, `apps/renderer`, and `packages/remotion-types` have `package.json` and TypeScript code but:
- No README in `apps/editor`, `apps/renderer`, `packages/mcp_server`, `packages/remotion-types`, or `skills/src`.
- No JavaScript/TypeScript tests.
- `pnpm-workspace.yaml` only includes editor/renderer/remotion-types, leaving the rest of the Node code ad-hoc.

**Action:** Add `README.md` files, at least one JS typecheck/test script per Node package, and decide whether the Remotion bridge is a supported feature or permanently optional.

### A6. No runtime observability / progress streaming

Long renders are opaque. Users must poll the filesystem or SQLite ledger. The v2 audit and `docs/ISSUES_BUGS.md` list this as open work.

**Action:** Implement Server-Sent Events (SSE), a lightweight web dashboard, or webhook callbacks with `ve watch <job-id>`.

### A7. FableCut preview is interactive and not automation-friendly

`ve preview` starts a Node server, opens a browser, and loops on `typer.prompt()`. This blocks CI/automation and has no test for the actual edit loop.

**Action:** Add a `--non-interactive` / `--timeout` mode that exports, renders, and finalizes without prompting, or split the interactive loop into a separate `ve preview --interactive` sub-mode.

### A8. No schema migration strategy for SQLite databases

`PersistentJobQueue` and `ProjectLedger` use SQLite. The schemas are created on first use but never migrated. A future column addition will break existing `.db` files.

**Action:** Add a simple migration table + `PRAGMA user_version` based migrator in `packages/state`.

## 6. Security & Operations

### S1. Secrets in `.env`

`.env` contains live API keys for ElevenLabs, FAL, OpenAI, Replicate, Poyo, OpenRouter, Sarvam, Pexels, YouTube, and SSH keys for ComfyUI pods. `.env` is in `.gitignore`, but it is present in the working copy.

**Observations:**
- `.env.example` misspells Sarvam as `SARAVAM_API` while `.env` uses `SARVAM_API`. The expected key name is unclear.
- No `config.example.yaml` equivalent shows which env vars are required for which provider.
- Some keys (ComfyUI pod SSH) may grant infrastructure access beyond API usage.

**Action:**
- Normalize env var names and document them in `.env.example`.
- Add a secret-scanning rule (e.g., `detect-private-key` pre-commit / ruff check).
- Consider moving non-API config (pod IPs/ports) into `config.yaml`.

### S2. Path traversal validation exists but is duplicated

`_validate_payload_paths`, `_resolve_payload_path`, and `_safe_filename` are defined in `handlers.py` and duplicated in spirit elsewhere (e.g., `pipeline.py`, `asset_ingestion/providers/visual/local_media.py`).

**Action:** Centralize path sanitization in `packages/state` or `packages/core` and reuse it across CLI, worker, MCP server, and providers.

### S3. No FFmpeg resource limits

FFmpeg commands are constructed throughout `packages/ffmpeg`. There is no global timeout, memory limit, or concurrency cap at the FFmpeg layer.

**Action:** Add a wrapper that applies `--runtime`, `--max-memory`, and `nice` / `ionice` defaults from `config.yaml`.

### S4. Cache eviction lacks size tracking

`ve cache-prune` scans the cache directory each time. There is no persistent size index, so pruning is O(n) and can race with active renders.

**Action:** Maintain a small SQLite or JSON ledger of cache entries with size/last-access, or use a directory-mtime heuristic.

### S5. Worker has no rate limiting

`ve worker --max-jobs N` limits job count but not resource consumption per job.

**Action:** Add per-job CPU/memory budgets and a global semaphore for FFmpeg/ML inference.

## 10. Reviewer Addendum (2026-08-04)

All claims in sections 2–9 were verified against the live codebase. Ruff (34), mypy (64), test count (1,117), and the single test failure all confirmed. The additional findings below were discovered during verification.

### R1. `output/` vs `outputs/` naming inconsistency

**Severity:** LOW

`.gitignore` ignores `output/` (singular) but the untracked directory is `outputs/` (plural). This suggests different parts of the codebase write to different output roots. A quick grep shows both forms exist:

- `output/` — used by some pipeline paths
- `outputs/` — appears as untracked in git status

**Action:** Standardize on one output root (recommend `output/` to match `.gitignore`) and update all references. Add both to `.gitignore` until the consolidation is complete.

### R2. `ve estimate → ve preview → ve finalize` workflow UX friction

**Severity:** LOW (design concern)

The cost-gate feature requires three separate CLI commands run in sequence. This is fragile (users can skip `estimate` and go straight to `preview`) and adds cognitive overhead. A single `ve run --cost-gate` that bakes estimate+preview+finalize into one flow would be simpler.

**Action:** Consider a unified `ve run --cost-gate` flag in a future UX pass. The three-command decomposition is fine as a v1 but shouldn't be the long-term API.

### R3. `pricing.yaml` staleness is advisory-only — no enforcement

**Severity:** MEDIUM

`PricingRegistry.is_stale()` warns when pricing data is old, but nothing *blocks* a render with stale prices. Combined with C4 (`update-pricing` doesn't actually fetch), this means budget estimates can silently drift from reality. A user who hasn't run `update-pricing` in weeks could get a cost estimate that's significantly wrong.

**Action:** After fixing C4 (real price fetching), add a `--require-fresh-pricing` flag (or make it the default) that refuses to run `ve estimate` or `ve run` when `pricing.yaml` exceeds its TTL. The `free_mode` config profile should bypass this check.

### R4. OpenRouter migration completeness not verified

**Severity:** LOW (needs audit)

The audit notes the default LLM provider switched to OpenRouter but doesn't check whether all LLM call sites actually route through `packages/llm/router.py` or if some still hardcode Ollama/OpenAI. A stale hardcoded provider would silently use the wrong model (or fail) now that the default changed.

**Action:** Grep for `openai`/`ollama`/`ChatOpenAI`/`ChatOllama` outside of `packages/llm/` and verify each site goes through the router. Add a mypy lint rule or test that asserts all LLM calls use the router.

### R5. Test suite slow-test diagnosis needed

**Severity:** LOW

The audit reports the fast suite reaches "~58% after 2 minutes" but doesn't identify the slowest tests. Without this data, the "mark slow tests" action item is guesswork.

**Action:** Before Phase 2, run `pytest --durations=30 -m 'not slow and not integration'` to identify the top offenders. Many may be doing real subprocess calls or file I/O without the `slow` marker.

### R6. `storyteller_to_fablecut` return value is discarded

**Severity:** LOW (related to C6)

Even after fixing the kwargs and adding `await` in C6, the return value of `storyteller_to_fablecut()` (a `StorytellerProject`) is not captured or used at line 715. The caller may need the returned project for subsequent steps in the handler.

**Action:** When fixing C6, check whether the caller needs the return value and capture it if so.
