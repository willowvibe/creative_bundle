## 3. What the branch gets right

- **Input checking.** Markers, routes, zooms, bboxes and coordinates are checked, and the error names the
  bad entry (`_coordinate`, `_markers`, `_route`, `_zooms` in `map_scenes.py`). A marker outside the map
  window is an error, not a pin drawn off the plate.
- **A composite scene needs its images.** `render_composite` raises when the layout needs more images than
  the scene has (`composite_scenes.py:739`), so the `{}` fallback in `from_scene_plan` cannot be reached.
- **Drafts are checked before money is spent.** `draft_script_from_topic` renders each draft in memory and
  checks its cues before the cost gate, and retries a bad draft up to 3 times.
- **The earlier fixes hold.** The layer window takes the scene's already-rounded end (no double rounding).
  Block markup is mounted as a sub-composition from a `<template>`, so the HyperFrames lint passes. The
  stub-asset audit only looks at files this build used (`stub_asset_ids(used_paths=...)`).
- **The camera maths is right.** `_camera_transform` derives the transform from two points shared by both
  views. The tests parse `@keyframes` and check both the scale and where each point lands.

## 4. Findings

### #329 Map strokes and the focus pin grow with the camera zoom

The camera scales `.map-camera`, which holds the whole map SVG. Marker pins and labels live in the separate
`.map-overlay` and keep their size, but everything drawn inside the SVG scales with the camera:

- the route (`stroke-width="4.6"`), country borders (1.2–1.4) and the graticule (1);
- the fallback focus pin (`r="26"`, `r="13"`, `r="5.4"`, `map_scenes.py:666-675`).

No path sets `vector-effect="non-scaling-stroke"`. The pilot zooms from a 24° window (`95,0.5,119,8`) to a
6° window (`100.0,0.7,106.0,3.25`), about 4×. In the 11.8 s frame the route is about 18 px wide and the focus
pin is about 100 px across, covering the "Malacca" label.

**Fix:** set `vector-effect="non-scaling-stroke"` on route, border and graticule paths. Move the focus pin
into `.map-overlay` as a tracked anchor, as the markers already are. Add a test that compares the zoomed
stroke and pin size with the base state.

### #330 Map art collides with the title block once zoomed

In the zoomed frame, the top edge of the map window cuts through the second line of the subtitle ("PORTS").
The subtitle wrapped to two lines, but the map window keeps a fixed position in the plate geometry. The
window's hard rectangular edges also read as a crop. The land fill stops on a straight line, and a thin pink
rule shows at the bottom right and left edge.

Natural Earth 110m is also visibly blocky at 4× (already noted in the pilot record).

**Fix:** put the top of the map window below the measured bottom of the title block, or clamp the subtitle to
one line. Feather or mask the window edge so the crop does not show. Switch to 50m geometry when the zoom
factor is above about 2.5×.

### #331 `focus` pin and markers draw two pins for one place

The fallback centre pin is only dropped when there is no `focus` and there are markers
(`map_scenes.py:884`). The pilot sets `focus: 101.5,2.5` *and* a Malacca marker, so two pins mark the same
idea about 40 px apart.

**Fix:** when markers exist, drop the focus pin unless the author asks for it (`focus_pin: true`), or have
the drafter stop writing `focus` when it writes markers.

### #332 Things the author wrote are dropped without a record

- **Zoom moves.** A zoom whose move cannot land before the cut is skipped by a `break`
  (`map_scenes.py:926`) with no log line and no QA finding. Its cue still matches the narration, so the cue
  gate passes even though the move never plays.
- **Cues.** The topic drafter turns off every cue the narration never says
  (`silence_unspoken_{map,composite,typographic}_cues`, called from `explainer_topic.py:170-189`). This
  stops the cue gate failing after narration has been paid for. But nothing records what was turned off, so
  a place the voice names in different words ("the Malacca Strait" vs "Strait of Malacca") appears on a
  timer instead of with the voice, and QA stays green.

**Fix:** log each dropped zoom and each switched-off cue (`map_zoom_dropped`, `cue_silenced`) and list them
in `qa.json` as warnings.

### #333 Captions drop spelled-out numbers

`align_words` matches the script against the STT text letter by letter. When the script says
"three hundred" and STT returns "300", nothing matches. `_offset_to_time` gives both words the start of the
next matched word, and the karaoke pass sets `end = next.start`, so they get zero length:

```
Only        5.24 → 5.52
about       5.52 → 6.30    (absorbs the time the voice spent on "300")
three       6.30 → 6.30    (zero length)
hundred     6.30 → 6.30    (zero length)
kilometres  6.30 → 6.78
```

The burned caption in the pilot reads **"Only about kilometres"**. Reproduce with:

```python
from video_editor_pipelines.explainer_timing import align_words
rec = [{"word": w, "start": s, "end": e} for w, s, e in [
    ("Only", 5.24, 5.5), ("about", 5.52, 5.76), ("300", 5.78, 6.28),
    ("kilometers", 6.3, 6.76), ("long,", 6.78, 7.0)]]
align_words(["Only about three hundred kilometres long,"], rec)
```

The bug is in engine code the branch did not touch. Any number, year or amount the script writes out in words
hits it.

**Status: fixed 2026-11-10** (see `docs/ISSUES_BUGS.md`): the spreading half below shipped; number
normalisation was not needed for correct timing.

**Fix:** rewrite numbers into one form on both sides before matching (digits ↔ words, ordinals, years). Then
spread each unmatched span's recognised time across its script words in place of zero-length entries. Add a
QA check that fails on zero-length caption words.

### #334 No QA gate looks at a plate mid-motion

HyperFrames lint, the safe-area check and the 28 px type floor all inspect the layout as written. #329–#331
only appear once the camera has moved, so the pilot passed every gate with these defects showing.

**Fix:** for any scene with camera moves, snapshot a frame after each move lands. Check it for text overlap
against the title and card boxes, and for pin or label overlap.

**#337, found after the audit.** While preparing to re-render `india-geography-1`, its QA showed a
failing `silent_gaps` check (7.08 s). The narration had speech for the whole of that span, but the
transcript did not: with no usable CUDA, the transcription settings fell back to `small` on CPU, and
`small` skipped the sentence "Those rivers carry the mountains to the sea: the Indus, the Ganga, the
Brahmaputra", which repeats the previous line's river names. Scene 5's map therefore started about 6 s
after its words. Turning off `condition_on_previous_text` did not help; `large-v3-turbo` on cpu/int8
heard every word in 71 s for 78 s of audio, so the fallback now keeps it.

**Found by frame-checking the india-geography re-render (`e34d161`).** The first re-render passed
every QA gate, but its frames showed three more map defects: the "Eastern Ghats" label cut to "Ea" after
the zoom (its pin landed just inside the frame while the label ran past it), a radial halo inside the
zoomed fill, and a 1 px hairline along the frame's top edge. A/B renders of the compiled page traced the
hairline to the `.map-window` clip-path meeting the fade mask. Labels now pick the side that fits the base
view and every landing (with the width estimate including letter-spacing), `map_motion` judges anchors by
where the pin lands and checks the base view too, the clip moved to the overlay, and the fade uses edge
gradients only.

**india-geography-1 re-rendered (2026-11-10).** `ve explain videos/2026-11-10/india-geography/script.md
--job-id india-geography-1 --image-provider poyo_ai -m assets/music/default.mp3 -y` reuses the original
narration and stills from the cache ($0). Every QA check passes, including `silent_gaps` (7.08 s → 0.78 s),
`map_motion` and `advisories`; scene 5's map now starts with its sentence. The first re-render used the
default `--image-provider auto` and no `-m`, which changed the cache keys and bought 7 new stills and a
music bed (about $0.275).

**Map animation upgrade and the route draw-on bug (`8eb0a9f`).** While adding richer animation for the
rivers and Ghats scenes, real frames showed that routes never drew on: they popped in fully drawn. Root
cause: the HyperFrames runtime only seeks CSS animations on HTML elements (it skips the SVG namespace),
so the SVG `stroke-dashoffset` animation ran on wall-clock time. Map animations now animate custom
properties on an HTML element that the SVG reads through `var()`; the generic compiler's SVG `draw`
already used this pattern, so no other scene type was affected. The same change adds real Natural Earth
rivers and named regions (worldwide), stepped "stutter" motion, great-circle routes, a leading route dot,
pin drops, and joint label layout. india-geography scenes 5 and 8 now use rivers and regions; the re-render
reused the cached narration and stills ($0) and passes every QA check.

**Known limits that remain.**
- #333: when STT merges words into one token, positions inside it are interpolated by character
  count, which is approximate for words of very different spoken length.
- #334 checks geometry, not pixels: it estimates label widths (0.62 × font size per character) and
  does not see artwork collisions. #330 removes the collision it was written for by construction.
- #330: the title fit assumes a one-line eyebrow; an unusually long eyebrow can wrap, but the map's
  transparent top band absorbs about four lines before any artwork is reached.
