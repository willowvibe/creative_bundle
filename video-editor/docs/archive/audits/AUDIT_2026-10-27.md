**Date:** 2026-10-27
**Baseline:** commit `01bbe17` (`feat(short): author the Day Master deck and give agy the canvas`) plus the uncommitted `agy_image.py` / `config.yaml` / `tests/test_agy_image.py` changes in the working tree.
**Scope:** The whole monorepo: correctness, concurrency, security, error handling, architecture and layering, configuration, tooling and CI, tests, docs, and repo hygiene.
**Prior audits:** `docs/archive/audits/AUDIT_2026-10-15.md` (render-graph direction), `docs/archive/AUDIT_2026-07-06.md`, and the July findings #52–#273 in `docs/ISSUES_BUGS.md`. New findings continue that numbering at **#274**.

## 1. Executive summary

The engine is in good shape at the unit level. **2,321 tests pass (2 skipped) in 4 min with xdist**, ruff is clean, and mypy `--strict` is clean on `apps/` and `packages/`. Recent subsystems (the Composition IR, content packs, cost gates, the LLM router) are well built: they fail closed, measure real output, and include regression tests.

The risk is in the parts that run **unattended or on someone else's input**. These are the job queue, the worker, and the MCP server. Together with the **structural debt** that has built up around them, they hold the real problems:

1. **The SQLite job queue hands the same job to every worker that asks at once.** This was reproduced in 40 of 40 trials with 4 processes. *Correction (same day):* the CLI's `_get_queue()` still uses the in-memory queue, so this is latent until the persistent queue is wired in (Phase 6). It must be fixed before that happens.
2. **Crashed jobs are never recovered.** `requeue_stale` exists but nothing calls it.
3. **The MCP server trusts `job_id` and path arguments.** It also runs paid providers with **no budget cap by default**. An LLM client, or a prompt injected into one, can write outside the work root or spend without limit.
4. **Two July architecture items were never finished:** B2 (one subprocess helper with timeouts) and B12 (payload path safety). 17 modules still shell out with no timeout.
5. **Layering is inverted.** Library packages import from apps, and the MCP server imports the CLI. Business logic lives in a 3,231-line `main.py` and in one-off `scripts/projects/*` composers outside the tested engine.

## 3. Findings

Severity follows the convention in `ISSUES_BUGS.md`. **HIGH** means money, data or safety is at risk in a normal configuration. **MEDIUM** means a robustness gap that will bite under load or failure. **LOW** covers hygiene and drift.

### HIGH

#### #274 HIGH — `PersistentJobQueue.dequeue` gives one job to several workers *(reproduced)*

> **Correction:** `ve worker`/`ve enqueue` use `InMemoryJobQueue` (`main.py:_get_queue`), so no shipped path runs two `PersistentJobQueue` consumers today. The bug is real and reproduced, but **latent**. **Fixed 2026-10-27.**

`packages/state/src/video_editor_state/queue.py:478-525`. The method `SELECT`s a pending row, then `UPDATE … SET status='running' WHERE id = ?`. The update has no `AND status = 'pending'` guard, and no `BEGIN IMMEDIATE` makes the read and the write atomic. The `threading.Lock` is per instance, so it does nothing across processes, and two `ve worker` processes are separate processes.

**Reproduction:** One job is enqueued and four processes, released by a barrier, each call `dequeue()`. **In 40 of 40 trials more than one worker received the job.**

**Impact:** Every extra worker re-runs the job. That re-bills the providers, and the workers race on the same `work/<job_id>/` files.

**Fix:** Claim with one atomic statement and check that a row came back:

```sql
UPDATE jobs SET status='running', started_at=:now
 WHERE id = (SELECT id FROM jobs WHERE status='pending' AND … ORDER BY … LIMIT 1)
   AND status='pending'
RETURNING *;
```

You could instead use `BEGIN IMMEDIATE` around the select and update. Add a multi-process regression test (the reproduction above is about 25 lines).

#### #275 HIGH — Jobs from a crashed worker stay `running` forever *(fixed 2026-10-27)*

`requeue_stale()` is defined on all three queue classes (`queue.py:96, 315, 641`), but no worker, CLI command or scheduler calls it. If a worker is killed (OOM, Ctrl-C, reboot) during a render, its job is never retried and never dead-lettered.

**Fix:** Call `requeue_stale(timeout)` at the top of the worker loop (`main.py:~3025`). Better, add a lease: a `heartbeat_at` column the worker refreshes, with reclaim based on heartbeat age instead of start time. Long renders legitimately take longer than the 300 s default.

#### #276 HIGH — The MCP server builds paths from an unsanitized `job_id` *(fixed 2026-10-27)*

`JobContext.__init__` (`packages/state/src/video_editor_state/job.py:15`) does `self.work_root / job_id` with no validation, and no `job_id` validator exists anywhere in the codebase. The MCP handlers then pass caller-supplied values straight through:

- `run_skill` defaults `work_root` to `f"/tmp/ve-{job_id}"` and also accepts arbitrary `work_root` / `output_root` (`video_editor_mcp/tools/pipeline.py:218-221`).
- `run_pipeline`, the vlog tools and the asset tools accept `job_id` (`vlog_skills.py:324`).

A `job_id` such as `../../home/<user>/.config/x` puts the work and output directories anywhere the process can write. MCP arguments are written by an LLM, so a prompt injection in a transcript, web page or file the agent reads is enough.

**Fix:** Validate in `JobContext`: `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, plus `resolve()` and `is_relative_to(work_root)`. Have the MCP server ignore client-supplied `work_root`/`output_root`, or constrain them to a configured data root.

#### #277 HIGH — MCP generation tools spend with no budget by default *(fixed 2026-10-27; `dubbing` still uncapped)*

`call_asset_tool` (`video_editor_mcp/tools/assets.py:111`) builds `AssetIngestionManager(ctx, config=config)` with no `BudgetGovernor`. `run_pipeline` attaches one only when the caller passes `budget`. The CLI paths have a cost gate and an approval step; MCP has neither. An agent looping on `generate_image` with a premium model, or one `run_pipeline` with music and b-roll, spends without a ceiling.

**Fix:** Add a server-wide default cap (for example `mcp.default_budget_usd` in `config.yaml`) applied to every MCP-created manager. Return the estimate in the tool result, and refuse above a per-call cap unless an explicit `approve_usd` argument is passed.

### MEDIUM

#### #278 MEDIUM — Worker payload path checks are partial (July item B12 unfinished) *(fixed 2026-10-27)*

`apps/cli/src/video_editor_cli/handlers.py` has a correct helper, `_resolve_payload_path` (resolve plus `is_relative_to`), but:

- `_validate_payload_paths` (line 39) **skips absolute paths entirely** and checks relative ones with `str.startswith`. The prefix check accepts `/work/abc-evil` for base `/work/abc`.
- These fields bypass both checks: `music_path` (354, 454), `presets_dir` (409, 431, 442), `project_dir` (720, 739, with `expanduser()`), and `media_dir` (164).

**Fix:** Route every payload path through `_resolve_payload_path`, and delete `_validate_payload_paths`.

#### #279 MEDIUM — 17 modules run subprocesses with no timeout (July item B2 unfinished) *(fixed 2026-10-27: every call goes through the shared runner; probe_duration consolidated; TID251 enforced)*

`video_editor_ffmpeg.run.run_ffmpeg` / `run_subprocess` exist, but these modules call `subprocess.run` without `timeout=`:

`fablecut_bridge/renderer.py`, `asset_ingestion/providers/visual/local_media.py`, `providers/audio/stub.py`, `providers/tts/stub.py`, `cli/composition_qa.py`, `cli/explainer_pipeline.py`, `ffmpeg/transitions.py`, `engine/broll_assets.py`, `skills/qa`, `skills/shorts_factory`, `skills/thumbnail`, `skills/broll`, `skills/screen_tutorial/click_detector.py`, `skills/graphics/renderer.py`, `skills/music/mix.py`, `skills/beat_sync`, `skills/motion_graphics`.

A wedged ffmpeg, or a Chrome process under HyperFrames, hangs the worker indefinitely. Combined with #275, the job never recovers. 45 files outside `packages/ffmpeg` build ffmpeg argv by hand, and 8 of them carry their own `probe_duration`.

**Fix:** Make `run_subprocess` (with a timeout, stderr capture and typed errors) the only way to run a process. Add a ruff `banned-api` rule for `subprocess.run` outside `video_editor_ffmpeg.run`.

#### #280 MEDIUM — The uncommitted `agy_image` change loses the atomic write *(fixed 2026-10-27)*

The working-tree diff to `providers/visual/agy_image.py` moves generation into a `TemporaryDirectory` under `/tmp` and finishes with `shutil.move(tmp, output_path)`. `/tmp` and `/mnt/data2` are different filesystems, so the move becomes copy-then-delete. A concurrent reader, or a crash mid-copy, sees a truncated PNG at the cache path. The previous code closed exactly that window with a sibling temp file and `os.replace`. The empty-cwd idea is sound, but keep the atomic write: after verifying, copy into `output_path.parent / f".{stem}.{uuid}.tmp"`, then `os.replace` it into place.

#### #281 MEDIUM — An `auto` request can quietly ship a stub asset *(fixed 2026-10-27 via `assets.strict` and the QA stub gate)*

`AssetIngestionManager._AUTO_FALLBACKS` (`manager.py:361`) maps every asset type to a stub provider. `stub_fallback` also replaces failed FAL calls. This is useful in development, but a provider outage or an exhausted budget can produce a "successful" render with placeholder imagery or silent audio. The content-pack path checks its outputs; the skills pipeline and MCP paths depend on whoever reads the logs.

**Fix:** Add a `strict_assets` / production mode, on by default for `ve short`, `ve explain`, the worker and MCP, that raises instead of falling back to a stub. Have QA fail any render whose manifest contains a `stub_*` provider.

#### #282 MEDIUM — MCP handlers block the event loop and leak temp dirs *(fixed 2026-10-27; run_pipeline→queue is phase 6)*

- `_handle_reframe` calls the synchronous `skill.run(...)` inside an `async` handler (`vlog_skills.py:398`), and so do several siblings. The stdio server cannot answer anything else until it returns.
- `run_pipeline` runs a full multi-minute pipeline inside one tool call, with no progress, cancellation or job id the client can poll.
- Every call `mkdtemp`s two directories (`pipeline.py:121-122`, `vlog_skills.py:327-328`, `assets.py:84`) that are never cleaned up.

**Fix:** Wrap sync skills in `asyncio.to_thread`. Make `run_pipeline` enqueue onto the persistent queue (after #274/#275) and return a job id, with a `job_status` tool. Put MCP work under one data root with a retention policy (`ve cache-prune` already exists).

#### #283 MEDIUM — Cost and budget failures are logged, not surfaced *(fixed 2026-10-27: degraded flag, marker, ledger issue, cost-report warning and qa.json warnings)*

In `manager.py`, a pricing failure in `_request_cost` (301) writes a ledger row with `NULL` cost. Failures in `_persist_budget_snapshot` (270) and in the ledger write (358) only log a warning. `ve cost-report` then under-reports, and a crash after a failed snapshot loses spend tracking. Add a per-job `cost_tracking_degraded` flag that the final report and QA show, and treat an unpriced paid call as a QA warning.

#### #284 MEDIUM — Blocking SQLite inside `async` methods *(fixed 2026-10-27)*

The queue and ledger run blocking `sqlite3` calls under a `threading.Lock` inside `async def` methods. In the worker and the MCP server this stalls the loop while another thread holds the lock. Use `asyncio.to_thread` around the DB section, or make the interface synchronous, which is honest about what it does.

## 4. Architecture drawbacks and recommended changes

### A1 — Inverted layering (packages depend on apps)

| Importer (library) | Imports from (app) |
|---|---|
| `asset_ingestion/scene_assets.py` | `video_editor_engine.models.scene_plan`, `.motion` |
| `fablecut_bridge/{exporter,importer,storyteller_export}.py` | `video_editor_engine.models.scene_plan` |
| `comfystudio_bridge/{exporter,importer}.py` | `video_editor_engine.models.scene_plan` |
| `mcp_server/tools/pipeline.py` | `video_editor_cli.pipeline.SkillsPipeline` |
| `mcp_server/tools/{commands,templates}.py`, `server.py` | `video_editor_engine.*` |

`ScenePlan`, `Scene` and the motion models are **domain types**, but they live in an app. As a result, every bridge and the asset layer drag in the whole engine app, and the MCP server cannot run without the CLI.

**Recommended:** Move `video_editor_engine.models.*` into `packages/core` (or a new `packages/models`), and leave a re-export shim in the engine for one release. Move `SkillsPipeline`, `MusicVideoPipeline`, `explainer_pipeline` and `short_pipeline` out of `apps/cli` into an orchestration package, for example `packages/pipelines`. The CLI, the worker and MCP then become three thin front-ends over the same orchestration API. Enforce the rule with `import-linter` in CI: `apps → packages`, never the reverse.

### A2 — The CLI is a god-module

`main.py` is 3,231 lines with 46 commands and 43 function-local imports. `pipeline.py` (1,533), `explainer_pipeline.py` (1,116) and `short_pipeline.py` (759) contain orchestration, not CLI code. A `commands/` directory already exists with 7 extracted commands, so finish that pattern: one module per command group (`commands/short.py`, `commands/explain.py`, `commands/queue.py`, …), with `main.py` reduced to registration. This also removes the `E402` per-file ignore.

### A3 — Too many ways to render a video

| Path | Location |
|---|---|
| Render graph → FFmpeg single pass | `core/compile_ffmpeg.py` |
| Composition IR → HyperFrames | `core/compile_composition.py` |
| Legacy per-stage skills chain | `SkillsPipeline(use_render_graph=False)`, still benchmarked with `--legacy` |
| `MusicVideoPipeline` | `cli/pipeline.py:1016` |
| FableCut direct renderer | `fablecut_bridge/renderer.py` |
| Hand-written composers | `scripts/compose_musical_video.py`, `scripts/projects/compose_cosmic_saju.py`, `compose_anime_tram.py`, `render_musical_plan.py`, `burn_musical_captions.py` |

The October 15 audit chose **one render graph / one IR**. The IR exists and is good, but the other paths were never retired, so fixes (loudness #272, zoompan #227, safe areas) must land in several places or silently miss some. **Recommended:**

- Delete the legacy per-stage path once the benchmark shows parity.
- Port the musical composer into the Composition IR (it is the last production template outside it).
- Move `scripts/projects/*` to `docs/archive` or `examples/`, with a note that they are not maintained.

**Status (2026-10-27):** the legacy per-stage path was retired rather than restored to parity. Its graphics stage fell back to FFmpeg (HyperFrames 0.8.208 no longer renders JSON plans), so keeping the two paths in step would mean maintaining a second renderer. The `--render-graph/--no-render-graph` flag, the `use_render_graph` parameter, the per-stage graphics/captions branch and the benchmark's `--legacy` mode are gone; the real-media graph benchmark completed in 139.3 s for a 74.2 s source. The `scripts/projects/*` archive is done (`examples/archive/`); the musical composer port remains open under A3 in `docs/ISSUES_BUGS.md`.

### A4 — Configuration has three loaders and two path strategies

- `packages/config` ("unified" loader), `asset_ingestion/config.py` and `llm/config.py` each search for `config.yaml` independently. Each falls back to `Path("config.yaml")` **relative to the current directory**, so running `ve` from a subdirectory silently loads nothing or a different file.
- `models.yaml` and `pricing.yaml` are found through `REPO_ROOT = Path(__file__).resolve().parents[N]`, defined in 6 places with N = 4 or 5. This breaks for any installed (non-editable) wheel, and it breaks quietly if a file moves one directory.
- The code itself flags the dual source of truth: `TODO(6b)` in `templates/base.py:69` and `storyteller_planner.py:237`.

**Recommended:** One `Settings` object from `packages/config`, resolved once per process (explicit flag → `VIDEO_EDITOR_CONFIG` → walk up from cwd to the repo marker), passed down or injected, and never re-read by leaf packages. Ship `models.yaml`/`pricing.yaml` as package data read through `importlib.resources`, with an override path in the config.

**Status (2026-10-27): implemented.** `Settings.load()` caches one resolved object per path/mtime/size; all runtime callers inject its asset/LLM sections. The loader methods remain only as compatibility APIs. Package-data YAML, the local overlay and the shared search order are in place, and TODO(6b) is closed.

### A5 — Workspace granularity

There are 36 uv workspace members, 24 of them single-module skill packages, each with its own `pyproject.toml`. The cost is real: the mypy path is a 36-entry string, `[tool.uv.sources]` has 36 lines, and every new skill touches 3 files. The root wheel packages `src/video_editor`, which is a 1-line module. Unless skills are published separately (they are not), collapse them into **one** `video_editor_skills` package with subpackages, and keep optional heavy dependencies (mediapipe, cv2, librosa) as extras.

### A6 — Undeclared system dependencies

Rendering depends on a globally installed `hyperframes` npm package (seen at `~/.nvm/.../node_modules/hyperframes`), Chrome, the `agy` CLI and FFmpeg ≥ 6.1 with specific filters. None of these is pinned. `package.json` declares only `typescript`, `@types/node` and `pxpipe-proxy`. A fresh machine, or a hyperframes upgrade, changes output silently.

**Recommended:** Pin `hyperframes` in `package.json` and invoke it through `npx`/a local bin. Extend `ve check-config` (or add `ve doctor`) to verify every binary and version, and write the versions into each job's `qa.json` so renders can be reproduced.

### A7 — The queue and worker are not built for more than one worker

Together, #274, #275 and #284 show that the queue was designed for one worker in one process. Before more automation (MCP enqueueing, scheduled builds) depends on it, give it:

- an atomic claim;
- a lease with heartbeat;
- idempotency keys per job, so a re-run reuses already-paid assets;
- a per-job lock file in `work/<job_id>/`, so two processes can never render into the same directory.

### A8 — Error-handling policy

There are 44 `except Exception` sites. Most log and continue, which is right for best-effort side channels (ledger, telemetry) and wrong for anything that affects output or money. Write the rule down, for example in `docs/ARCHITECTURE.md`: *best-effort side channels may log and continue; anything that affects the output file or spend must raise or mark the job degraded*. Then audit the 44 sites against it. The 5 in `manager.py` and 3 in `skills/verify` are the place to start.

## 5. The `agy` CLI image integration

`agy_image` is first in `assets.image_chain: [agy_image, poyo_ai, openrouter, fal_ai]`, so it serves every `auto` still. It works by running `agy --sandbox -p "<prompt>\n\nAspect: …\n\nSave the image to <tmp> and reply with the path." --output-format text`. In other words, it asks a **general-purpose coding agent**, in prose, to decide to use its image tool and then write a file. The process handling is careful: argv only, its own process group, kill and reap on timeout and on cancellation, a fresh output check, and 28 unit tests. The weaknesses come from the integration *shape*, not the code.

### How it behaves today

| Property | Observed |
|---|---|
| Latency | ~190 s for one 512×512 image (2026-10-23 build); the timeout was raised from 300 s to **600 s** in the working tree after deck cards timed out |
| Reliability | The agent sometimes reports success without writing a file. Two such cases are recorded in the comment at `agy_image.py:131-136` |
| What `--model` selects | The **driving chat model**. `agy models` lists only chat models (`gemini-3.8-flash-*`, `claude-*`, `gpt-oss-*`), not an image model. The image model the agent uses is unknown and unrecorded |
| Cost accounting | `cost: 0.0`, `model: "agy-default"`. The quota spent is invisible to `ve cost-report` |
| Concurrency | Semaphore of 2 (`manager.py:53`). At ~190 s per image, 25 stills take ~40 min |
| Security boundary | `--sandbox` restricts terminal commands only. The user's global `~/.gemini/antigravity-cli/settings.json` allows `command(*)`, and file tools are not confined to the cwd (the module docstring says so) |
| Version | `agy` 1.4.8 today; 1.4.6 on 2026-10-23. It is unpinned and self-updating, so behaviour changes underneath the pipeline |

### Findings

#### #291 MEDIUM — Most callers send `agy` no aspect, so stills come back square *(fixed 2026-10-27)*

`AGYImageProvider._aspect_line` reads only integer `params["width"]` and `params["height"]`. Only `short_pipeline._image_params` sets them, which was added in `01bbe17` ("give agy the canvas"). The other callers do not:

- `scene_assets._image_params` (`ve run`, `ve explain`, the worker) sends only `model`/`model_kwargs`.
- `storyteller_planner.py:428-437` sends `aspect_ratio: "16:9"`, which `agy` ignores.

The output is never checked against the requested aspect either: `_verify` returns the dimensions but accepts any shape. A square image then gets cover-cropped into 9:16 or 16:9, which cuts off subjects.

**Fix:**
- Normalise the aspect in one place: `AssetRequest.aspect()`, derived from `width`/`height` *or* `aspect_ratio`.
- In `_verify`, reject or flag any result more than ~3 % off the requested aspect, so the chain falls through to a provider that honours the aspect natively.
- Add a test per caller.

#### #292 MEDIUM — Failure costs too much time before the chain falls through *(fixed 2026-10-27: preflight, 30-min breaker, quota/auth classification, session fallback)*

One `agy` attempt can take 600 s before `poyo_ai` is tried, and the circuit breaker (`failure_threshold=3`, `recovery_seconds=60`) reopens after 60 s. That is shorter than a single run, so a degraded `agy` (quota exhausted, login expired, CLI update) is retried over and over at up to 10 min per still.

**Fix:**
- Run a **preflight** once per run (`agy` present, logged in, a tiny probe), and drop `agy` from the chain for the run if it fails.
- Give the breaker a per-provider recovery window (for example 30 min for `agy`).
- Classify `stderr` into quota, auth and other failures; a quota or auth failure should open the breaker immediately.
- Optionally set a **deadline-based fall-through**: if `agy` has not finished within N s and the budget allows, start the next provider and keep whichever result lands first.

#### #293 LOW — The provider records the wrong provenance *(fixed 2026-10-27)*

`metadata.model` is `"agy-default"` or the *chat* model name, never the image model. `cost` is `0.0`, and the `agy` version is not recorded. A later quality regression cannot be traced to a CLI update.

**Fix:** Record `agy --version`, the driving model, and whatever the agent reports about its image tool (see the structured output below). Log quota use as a separate `quota_units` field instead of folding it into `cost`.

#### #294 LOW — Stale module docstring *(fixed 2026-10-27)*

`agy_image.py:8` still says "the job's cache directory is the child's cwd". The working-tree change makes the cwd an empty temp directory, so the docstring now contradicts the code that sits next to the #280 atomic-write regression.

#### #295 MEDIUM — An `agy` child outlives an abruptly stopped parent *(found and fixed 2026-10-27: Linux PDEATHSIG on every child)*

`_run` starts `agy` with `start_new_session=True` and kills its group on timeout or cancellation. If the parent dies without unwinding the coroutine (SIGINT delivered outside it, SIGKILL, OOM), nothing kills the agent. A test-started run was still alive minutes after pytest was stopped. Fix with a Linux `PR_SET_PDEATHSIG` preexec (it fires on *thread* exit, so spawn from a long-lived thread), or with a per-run pidfile that the next run sweeps.

#### #297 MEDIUM — Concurrent queue initialisation kills starting workers *(found and fixed 2026-10-27)*

The phase-1 lease changed `_init_db` to add `heartbeat_at` with
`ALTER TABLE … ADD COLUMN`. On a fresh database several workers construct the
queue at once: the first creates the table, and the losers either hit
`database is locked` (the busy timeout was set after the WAL switch) or raise
`duplicate column name: heartbeat_at`. Reproduced in 17 of 20 trials with 8
processes. New databases now declare both columns, the busy timeout is set
before `PRAGMA journal_mode=WAL`, and schema creation retries lock/duplicate
races. Regression: `tests/test_queue_multiprocess.py`.

### Improvements to the integration, in order of value

1. **Make the call structured instead of conversational.** `agy` 1.4.8 has:
   - `--output-format json` and `--json-schema`, to require a reply like `{"path": str, "width": int, "height": int, "image_model": str}`. "Succeeded without a file" then becomes a schema failure with a reason.
   - `--disable-slash-commands`, so prompt text cannot expand into a skill or slash command.
   - `--effort low` and a fast driving model (`gemini-3.8-flash-low`). The agent only needs to make one tool call, so thinking effort is wasted latency.
   - `--print-timeout`, so `agy` ends its own turn cleanly before our hard kill.
2. **Give the agent only the tools the job needs.** Run `agy` with a dedicated settings/profile directory instead of the user's global one, where today `command(*)` is allowed. Use a dedicated `--agent` definition, or a `PreToolUse` hook that denies everything except image generation and `write_file` inside the run directory. That turns the documented prompt-injection gap ("file tools are not confined") into an enforced boundary. This matters because still prompts come from LLM-written scene plans, which can carry text from user scripts and researched web pages.
3. **Reuse one session for a batch.** `--input-format stream-json --output-format stream-json` keeps one `agy` process alive and runs one turn per NDJSON message. Batching a run's stills into one long-lived session removes the per-image startup and agent warm-up, which is a large share of the ~190 s. Keep the per-image file check unchanged.
4. **Write atomically again** (#280): verify in the empty workspace, then copy to a hidden sibling of `output_path` and `os.replace` it into place.
5. **Pin and record the CLI version.** Check `agy --version` against a supported range in `ve check-config`, and turn off self-update for the pipeline's profile if `agy` supports that.
6. **Weigh the free quota against a direct image API.** A direct image-model API call (the PoYo / OpenRouter `nano-banana` models already in the chain, or the Gemini API with an API key) takes seconds, takes `aspect_ratio` as a real parameter, returns bytes, and reports its model and cost. The case for `agy` is the free quota: at the cheap tier (`nano-banana-2-lite` on PoYo, see `docs/POYO_ROUTING.md`), 25 stills cost cents. Two choices make sense:
   - Keep `agy` for drafts and previews, where latency and aspect drift are acceptable, and put the direct API first for final renders, for example through a `--final` chain.
   - Keep `agy` first only after items 1–3 bring its latency and reliability close to the API's.

   Also confirm that driving a personal OAuth developer quota from an automated pipeline is within the service's terms. If it is not, the provider should be opt-in, not first in the default chain.

- **Test discipline:** the suite grew from 1,451 to 2,321 tests in two weeks, with xdist cutting runtime to about 4 minutes. Bugs are closed with regression tests.
- **Circuit breaker and budget reservation per provider call**, with release on failure (`manager.py:717-760`).
