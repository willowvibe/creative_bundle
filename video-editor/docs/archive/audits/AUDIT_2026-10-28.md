# Video Editor Engine — Repository Audit and Creative Gap Analysis

**Date:** 2026-10-28
**Baseline:** commit `4cc49b8` (`fix: measure the SFX level against the voice-only file`), clean tree apart from an untracked `.opencode/`.
**Scope:** the whole monorepo. This pass re-verifies the 2026-10-27 audit (`docs/archive/audits/AUDIT_2026-10-27.md`, #274–#297 and A1–A8), reviews the ~3,700 lines added since then (SFX providers, layerize/2.5D, the musical IR port, SFX QA), and compares the engine with a reference creator workflow (§5).
**Numbering:** new findings start at **#298**, continuing `docs/ISSUES_BUGS.md`.

## 1. Executive summary

Most of the work from the 2026-10-27 audit held up. Static checks are clean, the import-layering contracts hold, the suite grew to **2,662 passing tests**, and every HIGH finding from that audit is closed. The codebase is in better structural shape than at any earlier audit.

This pass found **two new HIGH issues**. Both come from the same pattern: a guard was added on one path while a second path to the same resource stayed open.

1. **#298: the worker's heartbeat stalls whenever a handler does blocking work.** That covers most jobs, including the main `run` job. Once a job outlasts `queue.stale_seconds` (900 s), a second worker reclaims it while it is still running. The job then burns retries, flaps between states, and may run twice and be billed twice. The lease added for #275 only works if the event loop is free, and today it is not.
2. **#299: MCP `run_command` bypasses every guard added for #276/#277.** `assets.resolve` takes client-supplied roots, `config_path` and plan filenames, and spends with **no budget**. `render.run` blocks the MCP event loop.

The new SFX providers have two **MEDIUM** issues:

- Openverse sends its API token to third-party audio hosts (#300).
- Freesound trusts the first search result's licence without checking it (#301).

On architecture, the two newest production paths (`ve short`, `ve musical`) run only from the CLI (#303). The async/sync boundary is inconsistent (A9), and MCP has two command surfaces with different safety models (A10).

On creative capability (§5), the reference video's main claim is that the harness matters far more than the prompt. That claim maps well onto this engine: it already has the harness, including design tokens, fail-closed gates, SFX derived from the Composition, a voice clone and cost control. **It lacks the creative half:**

- a director's brief;
- style transfer from a reference video;
- brand capture from a URL;
- a motion vocabulary beyond 10 primitives;
- beat-quantized timing;
- character consistency;
- an aesthetic critique loop that scores the render and fixes it.

## 3. Findings

Severity follows `ISSUES_BUGS.md`. **HIGH** means money, data or safety is at risk in a normal configuration. **MEDIUM** means a robustness or compliance gap. **LOW** covers hygiene and drift.

### HIGH

#### #298 HIGH — Blocking handlers starve the worker heartbeat, so a live job gets reclaimed

**Where**
- `apps/cli/src/video_editor_cli/main.py:494` (`_dispatch_message`): "Sync handlers are invoked directly", on the event-loop thread.
- `apps/cli/src/video_editor_cli/cli_support.py:1152` (`_heartbeat`): an `asyncio` task.
- `packages/pipelines/src/video_editor_pipelines/pipeline.py`: **zero** `to_thread` calls. `SkillsPipeline.run_async` calls the sync, FFmpeg-heavy skills directly (`skill.run(...)` at lines 456, 481, 493, 905, 981).
- `packages/state/src/video_editor_state/queue.py:667-735`: `_complete_sync` and `_fail_sync` update `WHERE id = ?` only.

**What happens**

1. While a sync handler or a sync stage inside an async handler runs, the event loop is blocked and the heartbeat task never fires. Affected handlers include `rough_cut`, `graphics`, `second_pass`, `captions_v2`, `music`, `sfx_mix`, `audio`, the bridge exports, the sync `render_fablecut_project` inside `_handle_render_fablecut`, and every non-explainer `run`.
2. After `queue.stale_seconds` (default **900 s**, `video_editor_config/__init__.py:136`), a second worker's `requeue_stale` reclaims the job, which is still running. A 10-minute vlog through the render graph alone runs at about 0.53× realtime, before b-roll, reframe and QA, so this threshold is reachable in normal use.
3. The second worker dequeues the job and waits 5 s on `job_lock`. It gets `JobLockError`, which falls into the loop-level `except` and calls `queue.fail(message)` on a job **it does not own**. That consumes a retry and puts the job back to `pending`. The cycle repeats until the job is dead-lettered, while worker A is still rendering it.
4. If worker A finishes between two of these attempts, the next worker gets the lock and **runs the whole job again**. That re-bills every paid provider. A's `complete()` can also overwrite a `dead_letter` status, because there is no status guard.

**Fix**

- Run every handler off the loop: `await asyncio.to_thread(handler, ctx, payload)` for sync handlers, and `to_thread` around each blocking stage in `SkillsPipeline.run_async` and `_handle_render_fablecut`. Alternatively, beat from a dedicated `threading.Thread` that does not depend on the loop.
- Add a lease token. `dequeue` writes `lease_id = uuid4()`. `heartbeat`, `complete` and `fail` require `AND status='running' AND lease_id=?`, and a lost lease raises in the owner instead of silently updating.
- When a worker gets `JobLockError`, it should **release** the claim (`status='pending'`, no retry increment, short `retry_after`). It must not `fail()` the job.
- Add a regression test: a sync handler that sleeps longer than `stale_seconds` (with `stale_seconds` set to about 1 s) and two worker processes. Assert exactly one execution and no retry consumed.

#### #299 HIGH — MCP `run_command` bypasses the MCP path and budget guards

**Where**
- `packages/mcp_server/src/video_editor_mcp/tools/commands.py:68-93` forwards any registry command with client JSON params.
- `apps/engine/src/video_editor_engine/commands/pipeline.py` defines the commands it forwards to.

**What it allows**

- `assets.resolve` builds `AssetIngestionManager(ctx, config=config)` with **no `BudgetGovernor`** (around line 226). The `mcp.default_budget_usd` and `per_call_cap_usd` limits never apply, so the uncapped spend #277 closed is reachable again through this command.
- `work_root` and `output_root` are free strings (defaults `"projects"` and `"outputs"`, relative to the server's cwd). They never pass through `make_job_ctx`/`_contained_root`, which reopens the out-of-root writes #276 closed.
- `plan_name` and `plan_out_name` are joined unchecked (`ctx.work_dir / "plan" / params.plan_out_name`), so `"../../../x.json"` writes outside the job.
- `config_path` is client-supplied. A config can set a provider's `base_url`, and the manager then sends that provider's API key to that host. Today this needs a YAML file already on disk, but an MCP client should never choose the config.
- `render.run` is a sync handler that `registry.execute` calls inline, so a full HyperFrames render blocks the stdio server.

**Fix**

- Expose only an allowlist of read-only commands (`probe.media`, `templates.list`, `pricing.cheapest`, `ticks.info`, `project.status`) over MCP.
- Route mutating commands through the guarded MCP tools: `make_job_ctx`, `job_budget`, `_safe_filename`, and no `config_path`.
- Longer term, move these guards into the registry itself (A10), so every front-end inherits them.
- In `registry.execute`, run sync handlers with `asyncio.to_thread`.
- Add tests: a `run_command assets.resolve` call with `work_root="/tmp"`, with `plan_out_name="../x"` and with no budget must each be refused.

### MEDIUM

#### #300 MEDIUM — Openverse sends the API bearer token to arbitrary audio hosts

`providers/audio/openverse_sfx.py:58-66, 100`. The client is built with `headers={"Authorization": f"Bearer {api_key}"}`. The audio file is then fetched with the **same client** from `chosen["url"]`, an absolute URL on whatever host the indexed result points to: Freesound CDN, Wikimedia, Jamendo, or any provider Openverse indexes. httpx applies the client's default headers to absolute URLs, so the token is sent to third parties.

Two more problems with that download:
- Nothing restricts the URL to `https`, or keeps it off private or loopback addresses.
- httpx does not follow redirects by default and `raise_for_status()` raises on 3xx, so any CDN redirect fails the cue.

**Fix:** download with a separate, unauthenticated client (`follow_redirects=True`, https-only, private-address check). Keep the bearer token on the `api.openverse.org` client only.

#### #301 MEDIUM — Freesound takes the first result without checking its licence, and puts the key in the URL

`providers/audio/freesound_sfx.py:110-124`.

- Openverse re-checks the licence of each result, but Freesound takes `results[0]` and relies entirely on the server-side Solr filter `license:("Creative Commons 0" OR "Attribution")`. If that filter matches loosely, or the API changes its labels, a CC BY-NC sound ships in a commercial video, which is a licence breach. Duration is not re-checked either.
- `_LICENSE_LABELS` maps only CC BY **4.0**. A CC BY 3.0 sound is labelled with its raw URL in `credits.txt`, so the credit stays technically valid.
- The key goes in the query string (`"token": self.api_key`). httpx's INFO log line `HTTP Request: GET <url>` includes the query, so any run with stdlib INFO logging enabled writes the key to its logs.

**Fix:**
- Accept a result only if its licence URL is in an explicit CC0, PDM or CC BY set (3.0 and 4.0, http and https), and its duration fits; otherwise try the next result.
- Send `Authorization: Token <key>` instead of the query parameter.
- Add a test with an NC result ranked first.

#### #302 MEDIUM — The short's `manifest.json` is not saved after the run *(open item, confirmed)*

`short_pipeline.py:870`: `ctx.manifest().stage_done("qa", …)` and the `layerize` stage (line 432) mutate the manifest, but only `estimate_short` calls `ctx.store.save()`. MCP `job_status` reads `manifest.json`, so it reports stale stages. On a copied project it reports the *source* project's stages. Fix as already written in `ISSUES_BUGS.md`, and also save when QA fails, so a failed build is visible too.

#### #303 MEDIUM — `ve short` and `ve musical` can run only from the CLI

`HANDLERS` (`packages/pipelines/src/video_editor_pipelines/handlers.py:886`) has no `short` or `musical` entry, and no MCP tool runs a content pack. These are the two production paths the recent saju shorts were built on. The A1 goal was "CLI, worker and MCP as three thin front-ends over one orchestration API", and it is not met for them. The estimate → approve → build spend flow (`check_approved_spend`) also has no queue form.

**Fix:**
- Add `short` and `musical` handlers that require an approved `cost_estimate.json` already in the job directory, so the queue never approves spend by itself.
- Add a guarded MCP tool `run_short(pack_path, approve_usd)` that enqueues the job and returns the job id.

#### #304 MEDIUM — The A8 error-handling policy is not enforced; 47 broad handlers have no comment

The policy (`docs/ARCHITECTURE.md`) says new broad handlers "need a comment naming the side channel they protect". The count rose from 119 to 130 in one day, and 47 have neither an inline nor a next-line comment. Examples:

- `asset_ingestion/manager.py:258, 338, 370, 436`
- `skills/export/export.py:184, 234, 267, 293`
- `skills/verify/verify.py:95, 127, 139, 443`
- `mcp_server/tools/*.py` (7 sites)
- `engine/commands/pipeline.py:321, 328` (`except Exception: pass`)

Most of these are probably fine, but nothing stops the next one from swallowing a spend or output failure.

**Fix:** enable ruff `BLE001` (and `S110` for `except…pass`) in CI and require `# noqa: BLE001 - <reason>`. Most existing sites already use that form, so the rule only formalises it.

## 4. Architecture drawbacks and recommended changes

A1–A8 from 2026-10-27 are done or tracked. These are the new structural issues.

### A9 — The async/sync boundary has no rule

Today the pipelines are sync functions that call `asyncio.run(...)` internally (`short_pipeline.py:359, 691`, `explainer_pipeline.py:989`, `pipeline.py:1052, 1579`). The handlers are `async` wrappers. `SkillsPipeline.run_async` is async in name only, because it runs sync FFmpeg stages on the loop. Some callers hop threads (`handlers.py:264`, the MCP tools); others do not (`_dispatch_message`, `registry.execute`, `_handle_render_fablecut`). #298 and #299's blocking `render.run` both follow from this.

**Recommended rule:** the orchestration core is **sync**, and the async edges (worker, MCP, control server) call it only through `asyncio.to_thread`. Provider I/O stays async inside `AssetIngestionManager`, bridged once by a single `run_sync` helper. Rename or remove `run_async` where nothing inside it awaits I/O, and add a test that fails if a handler blocks the loop for more than about 1 s.

### A10 — MCP has two command surfaces with different safety models

`video_editor_mcp/tools/*` uses `make_job_ctx`/`job_budget`. The engine command registry (`ve commands`, `ve control`, MCP `run_command`) uses neither. Whichever surface a new feature lands on decides whether it is safe.

**Recommended:** put the guards in the layer every front-end shares. Have a `JobContext` factory that takes a `TrustLevel` (CLI = trusted, MCP/control = untrusted) and applies root containment, filename validation, config-path refusal and a default budget. Registry commands then declare `mutates: bool` and `spends: bool`, and the untrusted front-ends refuse or cap based on those flags. Eventually the MCP tools themselves can become registry commands, which leaves one catalogue, one schema and one guard.

### A11 — Front-end parity is not tracked

#303 is one example. Nothing lists which capabilities each front-end exposes. Add a generated matrix to `docs/CLI_USAGE.md` with rows for capabilities and columns for CLI, worker command, MCP tool and registry id, plus a test that fails when a CLI production command has no worker handler and is not marked `cli_only`.

### A12 — The creative layer is a fixed vocabulary

`packages/core/src/video_editor_core/motion/primitives.py` registers 10 primitives: `drift`, `parallax`, `rise`, `pop`, `fade`, `fade_out`, `stamp`, `flip`, `lock`, `pulse`. Text motion and typographic scenes sit on top of those. That is the right design for reproducibility and QA, but it limits how good the output can look (§5). The IR has no escape hatch for a shot that needs bespoke animation code. §5.3 proposes one that keeps the gates.

### A13 — Run data still defaults to the checkout

`VIDEO_EDITOR_DATA_DIR` exists, but the default is unchanged and the checkout now holds 6.3 GB of media, up 1.1 GB in a day. Set `VIDEO_EDITOR_DATA_DIR` in `config.local.yaml`/`.env` for this machine, so the repo stays code-only for agents and indexers.

## 5. Creative gap analysis: the reference workflow vs. this engine

**Reference:** *How to Make Insane Motion Graphics With Opus 5.5*, Lukas Margerie, 2026-09-29, 20 min, 4K60, about 690 k views (<https://youtu.be/747ZnEtsRbg>). The video is sponsored by Fish Audio; treat its claims about the TTS provider as advertising.

### 5.1 What the video teaches

Its central claim is that "the prompt is only 10% of the outcome… the rest of the 90% is the harness". The model writes code: an HTML/SVG page rendered frame by frame in headless Chrome and then FFmpeg, or a framework such as HyperFrames or Remotion, or a mixed pipeline that composites over generated image and video. The harness around that code consists of:

1. **Motion-studio rules** in four parts:
   - a *render contract*;
   - *look rules that ban generic output*, such as centered text on a gradient;
   - *sound* rules;
   - a *feedback-loop* stage.
2. **Prompts that set a genre with known rules.** For example, "showreel for a resume" makes the model itself the subject, sets 15 s with 6–8 shots, and uses "go all out" as an effort multiplier.
3. **A real brand.** Logo, colours, fonts and real product screenshots, gathered by the agent from the product's site.
4. **A voice clone** with emotion control (Fish Audio MCP in the video).
5. **Style transfer from a reference video.** Extract a frame every 0.5 s, then write a style guide covering palette, type, shot lengths, transition types, camera moves, grain, and how text enters and exits. Then write a shot list in that style using real screenshots: "take the grammar of the reference, never its content".
6. **Persistent brand, style and spec files.** The spec list names UI components to animate: buttons, loaders, check marks, charts. Plus a *direction* line, for example "one container never cuts; every state is the same element changing size, radius and fill while its content swaps behind a short blur".
7. **A beat grid before any code.** A table of states on the beat that the user approves.
8. **Sound locked to picture.** Synthesise an original 120 BPM track in code and measure it into `beats.json` (BPM, beats, downbeats, hits). Add synthesised UI foley (a click per cursor press, a whoosh per container morph, a thump on the logo), then **retime the animation to the beats**.
9. **A director's brief** in 12 parts:
   - the film in one line;
   - references;
   - tools and keys;
   - a character bible (many views, proportions and expressions per character);
   - a beat sheet;
   - on-screen text;
   - a workflow gate;
   - a critique loop;
   - deliverables.
10. **A critique loop.** The model scores its own render against a rubric, fixes the low scores, and repeats until everything is 7–8 or higher. The showcase film took **163 model calls and about 7 hours**.
11. **Packaging as a skill** that asks for a URL, duration and format, and enforces hard rules.

### 5.3 Recommended roadmap to close the gaps

These are ordered by value per effort and fit around `docs/archive/plans/ROADMAP_2026-10-28.md` (transitions → SFX → 2.5D → film-look, mostly shipped).

1. **Critique loop (`ve critique`) — L, highest value.**
   - Render a contact sheet: one frame per shot plus frames at the transitions, using the existing `qa/frames` extraction.
   - A vision LLM scores a fixed rubric of 1–10 per axis: hierarchy, motion variety, depth, brand fit, picture–sound sync, legibility, pacing.
   - It returns **structured patches to the content pack or Composition** (change motion, retime, swap layout, recolour), never free-form code.
   - Apply the patches, re-render, and repeat until every axis is at least 8, or `max_rounds` or the budget runs out.
   - Store each round's scores in `qa.json`, and run under `BudgetGovernor`. The video's 163 calls show why a cap is essential.
   - The scores stay advisory. The pass/fail gates stay authoritative.
2. **Reference-style extraction (`ve style-from <video|url>`) — M.**
   - FFmpeg samples a frame every 0.5 s and runs scene-cut detection, which gives measured shot lengths.
   - A vision LLM writes `style.md` and **a DesignTokens draft** (palette, type pairing, shot-length distribution, transition mix, camera moves, grain/film-look, text entry and exit).
   - Enforce "grammar, not content" in the prompt and in a check that rejects copied logos or text.
   - Measured values (cut rate, palette by k-means) come from code, not the LLM.
3. **Look-ban gate — S.**
   - A composition QA check over the IR flags monotony: identical motion on every layer, a single font weight, every text centered on a full-bleed gradient, all scenes the same length (±10 %), no depth layers in 2.5D packs.
   - Warn first, then fail behind a `strict_look` flag. This encodes the video's "ban generic output" rule deterministically.
4. **Beat-quantized timing — M.**
   - `music: {bpm: 120, quantize: downbeat}` in the pack.
   - Generate or select music at that BPM, measure `beats.json` with the existing librosa path, and snap scene starts and motion cues to the nearest beat or downbeat within a tolerance, without moving a cue off its narration word by more than about 150 ms.
   - Emit a **beat-grid table** (`plan/beat_grid.md`) and show it in the estimate step for approval, alongside the cost.
5. **UI motion primitives — M.**
   - Add `morph` (shared-element FLIP with size, radius and fill, content swapped behind a blur), `cursor` (path + press with an auto click SFX cue), `draw` (SVG stroke-dashoffset), `type_on` (per-character), `wipe`/`mask_reveal`, `count_up` and `camera` (perspective dolly/orbit on a 2.5D stack).
   - Each primitive stays seek-safe CSS, so HyperFrames determinism and the frozen-parallax gate still hold.
   - `sfx_cues` already turns motion into foley, so `cursor` and `morph` get clicks and whooshes for free.
6. **Brand capture from a URL (`ve brand-capture <url>`) — S–M.**
   - Use `agent-browser`/Playwright to grab the logo (favicon, OG image, SVG), computed CSS colours and fonts, and full-page and component screenshots.
   - Fill `BrandProfile`, with assets stored under the data dir.
   - The user confirms the result before any build uses it.
7. **Director's brief schema — S.**
   - Extend `ContentPack` with optional `logline`, `references[]` (feeds item 2), `characters[]` (feeds item 8), `beat_sheet`, `on_screen_text`, `deliverables[]` (aspects and durations to render) and `direction`.
   - Validate them, and surface missing ones as advisory warnings.
8. **Character bible — M.**
   - `characters[]` with reference sheets (views, expressions).
   - Extend `AssetRequest` with `reference_images`.
   - Wire them to providers that accept image inputs (the nano-banana/Gemini-image family on PoYo and OpenRouter). Skip `agy` for character shots unless its structured call can pass references.
   - Add a QA check: CLIP/face-embedding similarity between the character's shots, with a threshold.
9. **Escape hatch for bespoke shots — M, behind a flag.**
   - A `layer: html` whose content is LLM-authored HTML/CSS for a single shot, rendered by HyperFrames inside the same Composition.
   - It must pass the same gates (seek-safety, frozen-frame, safe-area) and is size-limited and sandboxed: no network, no script access to the host.
   - This brings back the "model writes the animation" route from the video without giving up determinism for the rest of the film.

**What already beats the video's workflow:** spend is estimated and capped; outputs are measured, not assumed (loudness, cue timing, safe areas, SFX onsets, frozen parallax); sound effects are licensed and credited; and every build is reproducible from a pack. The gaps above are on the creative side. They can be added on top of this harness without weakening it.
