# Video Editor Engine — Long-Form Video Gap Analysis

**Date:** 2026-10-29
**Baseline:** commit `bc86a08` (`feat: brand capture from a page and per-character type-on`).
**Scope:** whether the engine can build the Cosmic Saju long-form video specified in the
Claude Docs page "Cosmic Saju — Long-Form Video: Reading 8 Characters" (34 shots, 8 chapters,
~10 min, 16:9), and what it needs to.
**Numbering:** new findings start at **#311**, continuing `docs/ISSUES_BUGS.md`.

---

## 1. Summary

About half of the video can be built today with `ve short` and a 16:9 content pack. That half covers
the still-image scenes with layerized parallax, scene SFX cues, a ducked music bed, the end card, and
the CJK, safe-area and look-ban checks.

The other half needs six things the engine does not have yet:

1. Chart scenes built from HTML/SVG components: pillars, element bars, the decade ribbon, the
   60-cycle rings and the medallion ring (#311).
2. A cloned voice of the creator, through Sarvam's voice-cloning API (#312).
3. Named scene transitions beyond crossfade (#313).
4. More than one visual per scene, including a screen recording (#314).
5. A long-form build made of chapter packs (#315).
6. YouTube packaging details: an `.srt` sidecar, a clear end-screen zone, and image edits or style
   references (#316–#318).

## 3. Findings

### #311 HIGH — chart scenes from HTML/SVG components

The spec builds every chart as HTML/SVG so that it matches the product. Those charts are the four
pillars with card flips, the element bars, the strength gauge, the feeding-cycle diagram, the
decade ribbon, the 60-cycle rings, the 12-medallion ring and the 3-2-1 countdown. The Composition
IR can already render `html` and `svg` layers, and `film_look.py` and the end card show the pattern.
`PackScene`, however, has no way to declare one.

**Fix:** add a `PackScene.graphic` block that names a component and its data, for example
`{component: four_pillars, data: {pillars: [...]}, over: i05_blur}`. Add a small library of Saju
components under `video_editor_core/graphics/` that emits static HTML/SVG with keyframe-only
animation, so a HyperFrames seek still reproduces the same frame.

The website's `FourPillarsChart` and `ElementBalanceBars` are React components in another repo, so
port them to static markup rather than importing them. The chart data comes from the Cosmic Saju
engine (`2ba8cc7`). The pack should take that data as JSON and never compute pillars itself.

### #312 HIGH — the creator's cloned voice through Sarvam voice cloning

The spec asks for the creator's own voice. Instead of recording 1,400 words by hand, clone the
creator's voice once with Sarvam and narrate through the existing Sarvam path. The voice then stays
consistent across the long-form video and the Shorts, and script edits re-render without a new
recording session.

Sarvam's documented API
([Voice Cloning overview](https://docs.sarvam.ai/api/api-guides-tutorials/voice-cloning/overview.md),
read 2026-10-29) offers the following:

| Endpoint | Purpose |
|---|---|
| `POST /voices/create` | Upload a reference clip (up to 50 MB; 10–15 s of clean single-speaker audio is recommended). Returns a reusable `voice_id` and an auto-transcribed `reference_text`. |
| `POST /voices/clone` | Generate speech: `text` (≤ 1,000 characters), plus exactly one of `voice_id` or `ref_audio`, and an optional `language_code`. Returns base64 audio. |
| `GET /voices`, `GET /voices/{voice_id}`, `DELETE /voices/delete/{voice_id}` | Manage saved voices. They are shared with Content Studio in the same workspace. |
| `POST /voices/clone/stream`, `GET /voices/clone/ws` | Streaming, in beta. Not needed for offline renders. |

Access is self-serve, with up to 50 cloned voices on the pay-as-you-go Starter plan. Billing is per
character; read the rate from Sarvam's pricing page before adding it to `pricing.py`. The docs use
`en-IN` in the voice-creation example and say the output language need not match the reference.
Consent: clone only a voice the user has the right to use, which here is the creator's own.

**What the engine needs:**

1. **A one-time setup command, `ve voice-clone create --name <n> --audio <clip.wav>`.** It calls
   `/voices/create`, then stores the returned `voice_id` and `reference_text` in project config
   (`config.local.yaml` or the brand profile). It never logs the reference audio. List and delete
   should map to the matching subcommands.
2. **A provider path.** `SarvamTTSProvider` today calls the Bulbul TTS endpoint with a built-in
   `speaker`. Add a `sarvam_clone:<voice_id>` voice-id prefix, which `_parse_voice_id` already
   splits on `:`. It routes the line to `POST /voices/clone` with `voice_id` and `language_code`,
   and decodes `audio`/`audio_b64` the same way.
3. **The 1,000-character limit.** Pack lines are well under it. A guard should still split on
   sentence boundaries and refuse silently truncated text.
4. **`[beat]` pauses.** The cloning endpoint documents no SSML, so render each beat as a measured
   silence between segments. `_concat_narration` already inserts `gap_seconds`; extend it with a
   per-line `pause_after`. Do not send `<break>` tags, which the voice would read aloud.
5. **Pricing and budget.** Add a `sarvam_clone` row to `pricing.py` so `BudgetGovernor` and the cost
   report see it. 1,400 words is about 8,000 characters, or 8 calls.
6. **QA.** The existing loudness and alignment gates apply unchanged. Add a one-time listening check
   to the setup command: synthesize a fixed test sentence so the creator can approve the clone
   before any paid long-form render.

A pack then reads:

```yaml
voice:
  provider: sarvam_tts
  voice_id: "sarvam_clone:<voice_id from ve voice-clone create>"
  language: en-IN
```

The pipeline needs no other change, because scene timing already comes from the measured narration.

**Pace and the reference clip.** The endpoint has no pace, speed or model parameter. Its only
quality switches are `enable_qc` (ASR plus a CER check, and regeneration on a prompt leak; off by
default) and `enable_vad` (trim the silence at either end; on by default). The clone copies the
pace, energy and emotion of the reference clip
([Prepare reference audio](https://docs.sarvam.ai/api/api-guides-tutorials/voice-cloning/how-to/prepare-reference-audio.md)),
so control the pace by recording the reference at the target delivery: the spec's slow,
one-listener read at about 145 wpm. One clip per delivery style is enough:

- **Clip:** 13–15 s, one speaker, mono 16-bit WAV at 16–24 kHz, in a quiet, low-reverb room. No
  music, no phone audio.
- **Languages:** cloning works across languages, so one `voice_id` serves every `language_code`.
  Record the reference in the main narration language. An accent in the reference carries over.
- **Pauses:** keep `enable_vad` on, so `gap_seconds` and `pause_after` are the only pauses.
- **Long-form renders:** turn `enable_qc` on.

### #313 MEDIUM — named scene transitions

`apply_scene_transitions` emits only crossfade and fade. The spec needs six. Most can be assembled
from primitives that already exist:

| Spec transition | Build from |
|---|---|
| Ink bleed | `mask_reveal` with an SVG `feTurbulence`/`feDisplacementMap` mask on the incoming scene |
| Mist dissolve | opacity ramp on the outgoing FG layer to full cover, then crossfade |
| Push-through | `camera` scale-in on the outgoing FG frame, then a cut at peak scale |
| Hanji turn | `flip` on the outgoing scene, with a paper-texture back face |
| Seal stamp | `stamp` on a seal layer, then a hard cut under it |
| Match cut | no code; the two stills are composed to line up (authoring note in the pack) |

**Fix:** extend `SUPPORTED_TRANSITIONS`, give `PackScene` a `transition_out`, and add a parity test
per transition. This is the "IR transitions" item at the top of `docs/archive/plans/ROADMAP_2026-10-28.md`.

### #314 MEDIUM — several visuals in one scene, and video media

S12 lays the chart over a blurred I05. S27 shows the ribbon, then cuts to I22. S28 slides glyphs,
then cuts to I23. S32 is a screen recording inside a tilted browser frame. A scene holds one
`PackStill`.

**Fix:** add `PackScene.shots: [{still | graphic | video, at_line}]`, so the visual changes on a
narration line boundary. Accept `video:` sources (local files only), paired with a `browser_frame`
preset. The IR already carries `media_kind: "video"`. Until then, splitting these into more scenes
works.

### #315 MEDIUM — long-form scale

The pipeline, its QA thresholds and its render times were tuned on shorts. One 10-minute
HyperFrames render is untested and is the slow path (`composition_router.py`).

**Fix:** support a `longform.yaml` that lists 8 chapter packs. Render each chapter as its own job,
since each is 60–100 s and close to proven size. Join them with the chapter transition from #313,
and run the QA gates per chapter and once on the joined file. That also lets one chapter be re-run
without paying for the others.

Rough cost: about 37 images (25 scenes plus 12 medallions, because layerize derives the depth
layers), plus about 8,000 characters of cloned narration. The Day Master deck cost $0.479 for 12
stills and TTS, so expect a few dollars. Confirm with `ve estimate` before rendering.

### #316 LOW — YouTube delivery details

- **Captions as a sidecar.** Add `captions.mode: sidecar`, which writes `final.srt` from the word
  timings and skips `burn_subtitles`.
- **End-screen zone.** Add a `youtube_end_screen` safe-area preset that keeps the right half clear
  in the last 20 s, and have the `safe_area` gate check it.
- **Music swells.** Add gain points on the music bed (`music.swells: [{at, db, duration}]`) for the
  cold open and the final reveal.

### #317 LOW — a third depth layer

The spec generates BG, MG and FG as separate images, keyed on transparency or #00FF00, under a CSS
`perspective` push with `translateZ`. Layerize derives two layers from one still. That is cheaper
and keeps the lighting consistent, so it should stay the default.

**Optional:** support `layers: generated`, with three prompts, an FFmpeg `colorkey` for green-screen
layers, and a `perspective` camera preset.

### #318 LOW — image edits and style references

I25 must be an edit of I04 (the same gate, now open), and the spec wants I01 as a style reference
for every image. `PackCharacter.reference_images` exists, but no provider sends references. This is
the P4.8 blocker. Check PoYo's edit and reference models first, then wire `reference_images` through
`AssetRequest.params`.

## 4. Order of work

1. **#312 Sarvam voice clone.** It is the smallest change, and it unblocks recording-free narration
   for this video and every Short.
2. **#311 chart scenes.** This is the visual core of chapters 1–6.
3. **#313 transitions.** These carry the chapter rhythm.
4. **#314 multiple shots per scene, and #315 chapter packs.**
5. **#316–#318.**

Chapter 0 (S01–S04) needs only stills, parallax, the voice and one push-through. It can be built as
a proof as soon as #312 lands, with the push-through replaced by a crossfade.
