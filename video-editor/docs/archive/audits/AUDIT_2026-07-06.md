### C1 — `requeue_stale` measures staleness from enqueue time, not dequeue time
**Severity:** CRITICAL (duplicate processing / data corruption under load)
**Files:** `packages/state/src/video_editor_state/queue.py:280-299`;
regression test `tests/test_queue.py:406-428` asserts the broken behavior.
**Found by:** STATE agent + CLI agent (independent confirmation).

`requeue_stale(timeout_seconds)` is meant to recover jobs lost to a worker
crash *between dequeue and complete/fail*. It compares
`datetime.fromisoformat(msg.created_at).timestamp()` against the cutoff — but
`created_at` is the **enqueue** time, not the dequeue time. `JobMessage` has no
`dequeued_at` field. A message that sat pending for 10 minutes under load, then
was dequeued 1 second ago, has `created_at ≈ 600s` ago and gets requeued by
`requeue_stale(300)` — even though a worker is actively processing it. Result:
two workers process the same job → duplicate side effects (double FAL
submissions, double ffmpeg renders, double billing).

The existing test `test_requeue_stale_returns_old_messages` encodes the wrong
semantics: it sets `created_at` 600s ago, dequeues, then asserts requeue.

**Fix:** Track `dequeue_time` alongside the message in `_in_flight`
(`dict[str, tuple[JobMessage, float]]` populated in `dequeue`) and compare
that. Update the test to assert a freshly-dequeued message is NOT requeued even
if `created_at` is old.

### C2 — Worker loop "no terminal state" guard double-fails retried messages
**Severity:** CRITICAL (silently halves the retry budget for every retried job)
**File:** `apps/cli/src/video_editor_cli/main.py:1822-1835`

When a handler raises and `max_retries > 0`, `_dispatch_message` calls
`queue.fail(message, repr(exc))`, which increments `retries` 0→1 and moves the
message to `_delayed` (not `_failed`). Back in the worker loop, both
`completed_count` and `failed_count` are unchanged (retried messages go to
`_delayed`), so the "no terminal state" guard (line 1826-1835) fires and calls
`queue.fail(message, "dispatch did not complete or fail")` a **second** time,
incrementing `retries` 1→2 and overwriting the real error reason with the
generic guard string. Net effect: each handler failure consumes 2 retries. A
job with `max_retries=3` is dead-lettered after ~1 handler failure instead of 3,
and the operator sees `"dispatch did not complete or fail"` instead of the
actual error.

All worker failure tests use `max_retries=0`, masking this.

**Fix:** Have `_dispatch_message` return a status literal
(`completed`/`failed`/`retried`/`unknown`) and branch on it; or only fire the
guard if `message.job_id` is still in `_in_flight`. Add a regression test with
`max_retries=3` and a failing handler asserting `retries` increments by 1.

### C3 — Worker loop orphans messages in `_in_flight` when `ensure_dirs()` raises
**Severity:** CRITICAL (permanent job loss)
**File:** `apps/cli/src/video_editor_cli/main.py:1811, 1837-1843`

The worker calls `_build_job_context(message).ensure_dirs()` before dispatch.
When the payload omits `work_root`/`output_root` (the warning at line 1793
fires), `ensure_dirs()` tries `mkdir /work` and `/output` → `PermissionError`
on most dev machines. The broad `except Exception` (line 1837) catches it, logs
"Worker loop error", and does `failed += 1` — but never calls
`queue.fail(message, ...)`. The message was already dequeued (removed from
`_pending`, added to `_in_flight`), so it is now orphaned: not in pending,
completed, failed, or dead-letter. It stays in `_in_flight` forever.

Distinct from closed #60 (which added `_in_flight`) and #80 (which added the
broad except) — the missing piece is that the except doesn't fail the orphan.

**Fix:** In the broad except, call `await queue.fail(message, repr(exc))`
before `failed += 1` (guard with `if message is not None`). Regression test:
enqueue a job with no `work_root`, run worker on an un-writable default,
assert the job lands in `_failed`/`_dead_letter`.

### C4 — Path traversal in `_handle_run` and `_handle_rough_cut` (multi-tenant)
**Severity:** CRITICAL (cross-tenant file read / arbitrary file copy)
**Files:** `apps/cli/src/video_editor_cli/main.py:1397-1453`
**Found by:** CLI agent; verified by reading the handler source.

Issue A25 (#76) fixed path traversal for `_handle_brief`, `_handle_audio`,
`_handle_align` via `_resolve_payload_path`. `_handle_run` and
`_handle_rough_cut` were missed. Both take `source`, `transcript_path`,
`config_path` from the payload and pass them straight to `Path(...)` with no
containment check:

- `_handle_run:1404` `source = Path(source_str)` — no `_resolve_payload_path`
- `_handle_run:1405` `tp = Path(payload["transcript_path"])` — no guard
- `_handle_run:1406` `cp = Path(payload["config_path"])` — no guard
- `_handle_rough_cut:1452-1453` same for `source` and `transcript_path`

In a multi-tenant worker, tenant A can enqueue `run` with
`source: "/home/tenantB/video.mp4"` and the pipeline reads tenant B's file.
`transcript_path` is worse: `RawFootagePipeline.transcribe` does
`shutil.copyfile(transcript_path, target_path)` (raw_footage.py:107) — an
arbitrary-file-read primitive that copies any readable file into the tenant's
work dir.

**Fix:** Call `_resolve_payload_path(source_str, [ctx.work_dir, ctx.output_dir],
"source")` (and for `transcript_path`, `config_path`) in both handlers before
any filesystem access. Regression test enqueuing `run` with `source` outside
the work root, asserting the job fails with "allowed roots".

### C5 — `output_name` / `plan_name` / `base_video` payload fields allow path traversal
**Severity:** HIGH (arbitrary file write via worker payload)
**Files:** `apps/cli/src/video_editor_cli/main.py:1480, 1485, 1563-1569,
1636-1637, 1668-1669`

Four+ worker handlers pass `output_name` (and `_handle_sfx_mix` passes
`plan_name`, `base_video`) from the payload directly into a path join with no
filename validation:

- `_handle_captions_v2:1480`, `_handle_music:1485` — `skill.run(output_name=...)`
- `_handle_align:1636-1637` — `transcript_dir / output_name`
- `_handle_audio:1668-1669` — `output_dir / output_name`
- `_handle_sfx_mix:1563-1569` — `ctx.work_dir / "plan" / plan_name`,
  `ctx.work_dir / "broll" / base_video`

A payload with `output_name: "../../etc/cron.d/evil.mp4"` escapes the intended
directory; for `_handle_audio`/`_handle_align` ffmpeg/shutil write the file →
arbitrary file write with controlled content. `_handle_sfx_mix` reads
`base_video` if it exists on disk → arbitrary file read.

**Fix:** Add `_safe_filename(name)` that rejects names containing `/`, `\`,
or `..`; apply to all `output_name`/`plan_name`/`base_video` payload fields.
Regression tests for each handler.

**Status:** Closed 2026-07-06. `_safe_filename` added in
`apps/cli/src/video_editor_cli/main.py` and applied to the affected handlers.
Regression tests in `tests/test_cli.py::TestPayloadFilenameValidation`.

### C6 — Replicate provider doesn't poll async predictions
**Severity:** HIGH (every Replicate model fails except flux-schnell on a fast run)
**File:** `packages/asset_ingestion/.../providers/visual/replicate.py:69-79`

`_get_client` sets `Prefer: wait`, but Replicate honors that only for ~10s. If
the prediction hasn't finished, the response is the prediction object with
`status: "starting"/"processing"`, `urls.get` polling URL, and `output: null`.
`_extract_output_url` returns `""` → `RuntimeError("No output URL in Replicate
response: ...")`. Any model slower than the wait window fails every time. No
test covers a non-synchronous response.

**Fix:** When `data.get("status") != "succeeded"`, poll `data["urls"]["get"]`
(with a timeout) until `status == "succeeded"` before extracting the output URL.

**Status:** Closed 2026-07-06. Added `_poll_until_complete` in
`packages/asset_ingestion/src/video_editor_asset_ingestion/providers/visual/replicate.py`.
Regression tests in `tests/test_replicate.py`.

### C7 — front-matter `notes:` silently dropped when `title:` absent  *(runtime-verified)*
**Severity:** HIGH (silent loss of user-authored brief metadata)
**File:** `packages/state/src/video_editor_state/project_brief.py:276`

`notes = _extract_notes(body) if not fields.get("title") else fields.get("notes",
_extract_notes(body))`. When front-matter has `notes:` but no `title:`,
`fields.get("title")` is falsy → the parser takes the `_extract_notes(body)`
branch and the front-matter `notes` value is silently discarded. Regression of
Bug #44: that fix added `notes` to `_BRIEF_YAML_KEYS` but the resolution logic
still requires `title` to be present for the front-matter value to win.

Verified at runtime: `project.md` with `---\nnotes: My front-matter notes\n---\n# Title\nBody.\n`
yielded `brief.notes = "Body paragraph."`, not `"My front-matter notes"`. No
test covers notes-without-title.

**Fix:** `notes = fields.get("notes", _extract_notes(body))` — always prefer
front-matter `notes` when present; the title field is irrelevant.

**Status:** Closed 2026-07-06. Fixed in
`packages/state/src/video_editor_state/project_brief.py`.
Regression test in `tests/test_project_brief.py::test_load_project_brief_notes_without_title`.

### C8 — No idempotency guard on `complete`/`fail` terminal transitions
**Severity:** HIGH (duplicate processing of completed jobs)
**File:** `packages/state/src/video_editor_state/queue.py:214-244`

Neither `complete` nor `fail` checks whether the message already reached a
terminal state. If a racing/buggy worker calls `complete(msg)` then
`fail(msg)` (or vice-versa), the message ends up in both `_completed` and
`_delayed`/`_failed`. After backoff the delayed copy is promoted to `_pending`
and dispatched again — duplicate processing of a job the caller believed
complete. A persistent backend (Redis/PG) implementing the same ABC inherits
the hole.

**Fix:** Track `_terminal: set[str]`; both methods early-return (or log) if
`message.job_id in _terminal`. Or check `_in_flight` membership before
transitioning.

**Status:** Closed 2026-07-06. Added `_terminal` set and guarded
`complete`/`fail` in `packages/state/src/video_editor_state/queue.py`.
Regression tests in `tests/test_queue.py::TestTerminalIdempotency`.

### C9 — FAL IMAGE responses lack content-type/byte validation
**Severity:** HIGH (corrupt bytes permanently poison the FAL image cache)
**File:** `packages/asset_ingestion/.../providers/visual/fal_ai.py:105-109`

The A18 fix added `save_audio_response` (content-type + magic-byte sniff) to
audio providers but not the FAL visual provider. It writes
`media_response.content` to disk with no validation, and for IMAGE assets
`probe_media` is NOT called (only VIDEO runs the probe). A 200-OK HTML/JSON
error body from the FAL CDN is silently written to `cache_dir/<key>.png`, the
meta is written, and every subsequent run returns the corrupt bytes as a cache
hit. For VIDEO the probe catches it; for IMAGE there is no guard.

**Fix:** Sniff PNG/JPEG/WebP magic bytes after `raise_for_status` for IMAGE
assets; raise `MediaContentError` carrying the first 256 bytes on mismatch.

**Status:** Closed 2026-07-06. Added `_validate_image_bytes` in
`packages/asset_ingestion/src/video_editor_asset_ingestion/providers/visual/fal_ai.py`.
Regression test in `tests/test_fal_ai.py::test_fal_image_rejects_non_image_bytes`.

### C10 — MP4/M4A audio content sniff checks `ftyp` at the wrong offset  *(runtime-verified)*
**Severity:** HIGH (valid MP4/M4A audio responses rejected as corrupt)
**File:** `packages/asset_ingestion/.../providers/_media.py:34-39`

`audio_signatures` includes `b"ftyp"` and checks `head.startswith(sig)`. MP4/M4A
files start with a 4-byte box size, then `ftyp` at offset 4. `head[:4]` is the
size, so `head.startswith(b"ftyp")` is always False for real MP4 files.

Verified: `_is_audio_content()` on `demo/music.m4a` (valid M4A, header
`00 00 00 1c 66 74 79 70 4d 34 41 20`) returned `False`. Latent today only
because all HTTP audio providers request MP3 (detected via `ID3`/`\xff\xfb`),
but any provider returning M4A/AAC-in-MP4 (e.g. ElevenLabs
`output_format=mp4_44100_128`) would raise `MediaContentError` on a valid
response.

**Fix:** `b"ftyp" in head[4:16]` (the ftyp box is always at offset 4 in a
valid MP4).

**Status:** Closed 2026-07-06. Fixed in
`packages/asset_ingestion/src/video_editor_asset_ingestion/providers/_media.py`.
Regression tests in `tests/test_asset_ingestion.py::TestMediaContentSniffing`.

## MEDIUM

> **2026-07-08: all findings in this section are closed with regression tests (472 → 496 tests passing, mypy 0, ruff clean).**

### C11 — `remotion_renderer.py` subprocess calls have no timeout and don't capture stderr
**File:** `apps/cli/src/video_editor_cli/remotion_renderer.py:32, 103`

Both `subprocess.run` calls (pnpm build, pnpm render) use `check=True` with no
`timeout=` and no `capture_output=True`. Distinct from A12/A13 (#63/#64) which
only hardened the FFmpeg package and HyperFrames. A hung pnpm (stdin wait,
network stall, OOM) wedges the worker indefinitely; on failure the user sees
only `"Command 'pnpm' returned non-zero exit status N"` with no stderr.

**Fix:** Add `timeout=600` and `capture_output=True`; include `exc.stderr` in
the raised exception.

### C12 — FAL poll transient 5xx retries the WHOLE job (re-submits, wastes credits)
**File:** `packages/asset_ingestion/.../manager.py:244-249` + `fal_ai.py:170-171`

`_generate_one` is wrapped in tenacity `stop_after_attempt(3)`. A transient
`502/503/504` from the FAL **status/response** endpoint (inside
`_poll_until_complete`) is retryable, so tenacity re-invokes the whole
`_generate_one` — re-submitting the FAL job from scratch. The original job is
abandoned (still running on FAL's side, burning credits). A 1-second poll blip
costs a full duplicate submission (~$0.50/video). The poll loop has no internal
retry.

**Fix:** Wrap the per-poll `client.get(...)` in an inner 1-2 attempt retry
with backoff, or catch 5xx inside `_poll_until_complete` and continue the loop.

### C13 — Circuit breaker is a no-op for FAL (the provider that needs it most)
**File:** `packages/asset_ingestion/.../manager.py:354-363`

The FAL fallback catches the FAL exception and returns a stub `AssetResult`
(success). `_resolve_one` then calls `record_success()`, so the per-provider
circuit breaker **never opens** during a FAL outage — every request still
enters the semaphore, calls FAL (3 attempts each with backoff), then falls
back. A 1-hour outage means every batch pays the full 3-attempt retry cost on
every request instead of fast-failing after the first few.

**Fix:** Call `record_failure()` on the original FAL exception BEFORE the
fallback returns, or count the fallback as a "degraded success" that still
accrues partial failures.

### C14 — `ve transcribe <missing-job>` leaks an opaque `FileNotFoundError`
**File:** `apps/cli/src/video_editor_cli/main.py` (transcribe command path)
**Found by:** runtime exercise.

`ve transcribe nope` (job that was never ingested) raises a raw
`FileNotFoundError: [Errno 2] No such file or directory: 'work/nope/ingest/manifest.json'`
with a full traceback instead of a friendly "job 'nope' not found — run `ve
ingest` first." Same applies to `ve analyze`/`ve plan`/`ve cut` on a missing
job. The ingest path correctly raises a typed `NoSourceMediaError` (A8 fix);
the downstream commands don't have the equivalent guard.

**Fix:** Add a `_require_job(work_dir, job_id)` helper that raises a typed
`JobNotFoundError` with an actionable message when `<work_dir>/<job_id>` or its
manifest is missing; call it at the top of each downstream command.

### C15 — `_key_locks` dict grows unbounded (memory leak in long-running workers)
**File:** `packages/asset_ingestion/.../manager.py:145-146, 204-208`

`_key_lock` creates a new `asyncio.Lock` per cache key and stores it in
`self._key_locks`. Locks are never removed. A long-running worker processing
many distinct prompts accumulates locks forever (~100 bytes each; ~1MB/day at
10k unique assets/day).

**Fix:** Delete the key from `_key_locks` after generation if no other
coroutine is waiting (refcount or `WeakValueDictionary`), or periodically sweep
unlocked keys.

### C16 — `forced_alignment_response_to_transcript` raises `TypeError` on `None` timestamps
**File:** `packages/asset_ingestion/.../scene_assets.py:252-253`

`float(w.get("start", 0.0))` only defaults when the key is **absent**. If
ElevenLabs returns `{"text": "hello", "start": null, "end": null}` (non-speech
alignment tokens), `float(None)` raises `TypeError`. The converter aborts and
the user gets an opaque traceback. The alignment provider only validates that
`words` is a non-empty list, not that each word has numeric timestamps.

**Fix:** `float(w.get("start") or 0.0)`, or a `coerce_float` helper that
handles `None`/`""`/missing uniformly.

### C17 — SFX cache-key docstring contradicts the implementation
**File:** `packages/asset_ingestion/.../scene_assets.py:131-135` vs `models.py:43-56`

`sfx_requests_for_scene` docstring says "keyed on the scene id so each scene
gets its own SFX clip." But `AssetRequest.cache_key()` hashes only
`asset_type`, `prompt`, `provider`, `params`, `output_ext` — NOT `asset_id` or
`scene_id`. Two scenes with the same `visual_description` (same prompt) get the
SAME cache key; scene B gets a cache hit on scene A's SFX clip. Either the
docstring is wrong or the cache key is missing `scene_id`.

**Fix:** Add `asset_id`/`scene_id` to `cache_key()` for true per-scene assets,
or fix the docstring to say "keyed on prompt; scenes with the same
visual_description share a SFX clip."

### C18 — `ElevenLabsMusicProvider` silently truncates `duration_seconds` to int
**File:** `packages/asset_ingestion/.../providers/audio/elevenlabs_music.py:62`

`duration = int(request.params.get("duration_seconds", DEFAULT_DURATION_SECONDS))`.
A caller passing `5.5` silently gets `5`. ElevenLabs music API accepts float
durations and bills per second; `music_request()` types its param as `int` but
callers can pass floats via `AssetRequest.params` (untyped dict). The SFX
provider correctly uses `float(...)` (line 61) — inconsistent.

**Fix:** `float(request.params.get("duration_seconds", DEFAULT_DURATION_SECONDS))`.

### C19 — Inline `key_segments` parser breaks items containing commas
**File:** `packages/state/src/video_editor_state/project_brief.py:200-208`

The inline-list branch does `inner.split(",")`, splitting on every comma
including commas inside quoted items. `key_segments: ["intro, hook", "close"]`
parses to `["intro", "hook", "close"]` (3 items) instead of
`["intro, hook", "close"]` (2). The writer always emits the multi-line form, so
roundtrip is unaffected; only hand-edited inline lists with comma-bearing items
break.

**Fix:** Drop inline-list support (force multi-line, raise on `[`), or use a
state machine that respects quote boundaries.

### C20 — `JobContext.from_manifest` re-homes the manifest on save
**File:** `packages/state/src/video_editor_state/job.py:38-49`

`from_manifest(manifest_path)` loads a `JobManifest` from an arbitrary path and
sets `ctx.store.manifest = manifest`, but `ctx.store.manifest_path` stays
`<work_dir>/manifest.json`. If `manifest_path != <work_dir>/manifest.json`,
every subsequent `store.save()` writes to `<work_dir>/manifest.json`, not the
original path — the loaded manifest is silently re-homed. Dead code today (no
caller), but it's a public exported API with no test.

**Fix:** Align `ctx.store.manifest_path` with `manifest_path`, or document the
constraint. Add a roundtrip test.

### C21 — CLI command-argument inconsistency (job-id flag vs positional)
**File:** `apps/cli/src/video_editor_cli/main.py` (CLI definitions)
**Found by:** runtime exercise.

`ve ingest` and `ve rough-cut` take `--job-id/-j` as an **option**, while
`ve transcribe`, `ve analyze`, `ve plan`, `ve cut`, `ve graphics`, `ve
captions`, `ve music`, `ve export`, `ve second-pass`, `ve plan-script` take
`JOB_ID` as a **positional** argument. `ve enqueue`/`ve worker` use `--job-id`
again. This is a real user-facing inconsistency: a user who just ran
`ve ingest src -j foo` will naturally try `ve transcribe -j foo` and get

### C31 — `insert_broll` shows a frozen last frame instead of playing the b-roll clip
**Severity:** HIGH (b-roll overlay is broken for any motion content)
**File:** `packages/ffmpeg/src/video_editor_ffmpeg/broll.py:32-36`

The overlay clip is built as `[idx:v]trim=duration={duration},format=yuva420p,

clip and the test passes.

`start`: `trim=duration={duration},setpts=PTS-STARTPTS+{start}/TB,

`subprocess.run` in `graphics.py:224` and `second_pass/renderer.py:101`

Each skill has its own copy of `_concat_segments` calling
`subprocess.run(..., check=True, capture_output=True)` with no `timeout=`. A
hung concat (broken seek, infinite lavfi source, corrupt segment) wedges the
worker. A12 covers the `packages/ffmpeg` subprocess calls but not these
skill-level copies. These also bypass the central
`video_editor_ffmpeg.cuts.concat_segments` (which uses the guarded
`run_ffmpeg`).

**Fix:** Route all skill concat/degenerate-clip calls through
`video_editor_ffmpeg.cuts.concat_segments` / `run_ffmpeg` (600s default
timeout). Deduplicate the three copies.

### C42 — `detect_silence` drops intermediate unpaired `silence_start` events
**Severity:** LOW
**File:** `apps/engine/src/video_editor_engine/analysis/silence.py:71-74`

`zip(starts, ends, strict=False)` pairs the first `len(ends)` starts with the
available ends, and only the *last* unpaired start is appended as a trailing
region. When `len(starts) - len(ends) > 1`, intermediate unpaired starts are
silently lost. Real-world frequency is low (FFmpeg normally emits balanced
start/end pairs except for the final trailing silence), but it is a correctness
gap and the trailing region's duration is hardcoded to `min_duration` rather
than the true remaining silence.

**Fix:** After zipping, append `(s, s + min_duration)` for *every* unpaired
start (index `>= len(ends)`), or raise if more than one unpaired start is
observed. Consider probing the file duration to bound the trailing region.
