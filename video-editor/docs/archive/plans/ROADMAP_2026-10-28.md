# Roadmap — 2026-10-28

What we plan to add to the engine next, gathered from the 2026-10-27/28
discussions (audit follow-up, 2.5D research, sound design, infrastructure).
Open bugs and audit items stay in `docs/ISSUES_BUGS.md`; this file holds the
forward plan and the reasons behind it.

**Already landed since the audit:** A3 legacy render path retired (`3d84524`);
A4 one `Settings` object injected into the pipelines (`ac5c157`, `d942eb4`).

## Priorities

Ordered by dependency and value. Items 1, 2 and 4 are Composition IR features,
so each one reaches shorts, explainers and (after the port) musical videos at
once.

### 1. Scene and layer transitions in the Composition IR

- `CompositionScene.transition_in` is rejected today
  (`packages/core/src/video_editor_core/composition.py`,
  `_transition_is_not_emitted`). Make the compiler emit it.
- Map transitions to plain crossfades plus the HyperFrames registry's shader
  transitions (14 blocks, e.g. `light-leak`, `whip-pan`, `cinematic-zoom`,
  `sdf-iris`, `domain-warp-dissolve`; the registry advises at most two per
  video).
- **Unblocks** the last open A3 item: porting
  `scripts/compose_musical_video.py` + `burn_musical_captions.py` to the IR,
  which depends on FFmpeg `xfade` today. It also gives sound design (item 2) a
  cue to land on.

### 2. Sound design

The `ve short` and explainer paths place no sound effects today, so every
stamp, pop, flip and slide is silent. `skills/sfx_placement` only maps spoken
keywords in the transcript to ElevenLabs prompts.

- **Cue table:** motion primitive → sound (`stamp` → hit, `pop` → click,
  `flip` → card flip, `rise`/`fade`/transitions → soft whoosh). Cue times come
  from each layer's start in the Composition, so no detection step is needed.
- **Sources, in order:**
  1. [earshot](https://github.com/Leonxlnx/earshot) code-synthesized bank
     (`sfx`, 252 sounds) and `forge` recipes — generated, so no stock licence.
     MIT code; CLAP (Apache-2.0) and AST (BSD-3) models; CPU only, ~1.1 GB
     one-time download. Run it as an MCP server (models stay loaded) in its own
     pinned environment; it is young (v0.4).
  2. ElevenLabs SFX (already integrated).
  3. Openverse audio, restricted to CC0 / Public Domain Mark / CC BY
     (`license_type=commercial,modification`). Openverse is an index, not the
     licensor: record title, creator, source URL and licence per sound in the
     job manifest and emit `credits.txt` for the video description. Never use
     NC, ND or (by default) SA.
- **Mix** under the voice-over with the music skill's existing ducking.
- **QA:** an earshot listening check (`timeline`, `measure`) for sync and
  level. Treat `critique` as advice only — its reference set is 7 product
  launch films, not our formats.
- The Clipwing *Real SFX* skill is a reference for ducking and loudness checks;
  we build the placement natively instead of reading the rendered timeline
  back.
- **First step — done 2026-10-28:** a no-spend earshot trial on
  `videos/2026-10-27/day-master-deck/day_master_deck.mp4` (doctor, timeline,
  measure, critique, a few rendered bank sounds). Earshot's cut detector
  matched all 12 scene boundaries within a frame; 67% of cuts had an onset
  within 100 ms and one cut was silent. `critique`'s "no music" verdict is
  expected for a narration-only pack. Results:
  `../tool-lab/trials/2026-10-28-earshot/README.md`.

### 3. 2.5D layer separation (`layerize`)

Deferred in the HyperFrames spec §11; supersedes the DepthFlow part of
`../tool-lab/trials/2026-10-22-motion-canvas-local-i2v/README.md`.

- **Spike first** (about 1 day, isolated environment, RTX 3050 4 GB): compare
  depth models on three real stills and measure VRAM, time and edge quality.

  | Job | Candidate | Licence |
  |---|---|---|
  | Depth | **DA3MONO-LARGE** (0.35B, monocular relative depth), DA3-SMALL / DA3-BASE, Depth Anything V2 Small | Apache-2.0 (DA3-LARGE/GIANT are CC BY-NC — do not use) |
  | Subject cut-out | BiRefNet, BEN2 | MIT (avoid RMBG-2.0: non-commercial) |
  | Fill behind subject | LaMa (IOPaint / `simple-lama-inpainting`) | Apache-2.0 |
  | Text-prompted objects | SAM 3 | SAM License, gated weights |
  | Full RGBA decomposition | Qwen-Image-Layered (20B) | Apache-2.0; needs a rented GPU |

  Depth Anything 3 installs from source (`pip install -e .`, xformers
  recommended) and ships a `da3` CLI and Python API.
- **Spike — done 2026-10-28:** on the RTX 3050 the chain fits sequentially:
  DA3MONO-LARGE at 1280 peaks at 2.34 GB (0.8–1.4 s/still), BiRefNet bf16 at
  1024 peaks at 3.06 GB (0.7–1.0 s), LaMa peaks at 0.82 GB (0.5–2.8 s).
  Mono-large has the best depth edges and the smoothest flat regions; BiRefNet
  must run in bf16 (fp32 OOMs), BEN2 is the lighter alternative with softer
  edges. A resident Ollama embedding model holds 1.2 GB and must be unloaded
  before BiRefNet. Human review of edge quality is still pending. Full results:
  `docs/archive/plans/LAYERIZE_SPIKE_2026-10-28.md`.
- **Layerize stage** after image generation: writes `depth.png`, `fg.png`
  (alpha) and `bg_filled.png` to the asset cache; opt-in per scene with a
  content-pack field such as `layers: auto`.
- **HyperFrames renders the motion:** a `parallax` primitive moving 2–3 media
  layers at different rates (fits the current CSS compiler), then a WebGL
  depth-displacement variant. We do **not** adopt DepthFlow: AGPL-3.0 and a
  second renderer, which is what A3 just removed.
- **Cheaper path:** we generate the stills, so prompt for the subject on a plain
  background plus a separate background plate and skip segmentation.
- **QA:** cut-out halos, edge stretch, frozen frames.

### 4. Film-look effects

Grain, vignette and a 3D-LUT colour grade landed as the design's `grade`
(sparse `data-color-grading`); the light leak landed as a design token that
emits a seek-safe full-canvas overlay at the first and/or last cut. The
compiler warns above the registry's two-flourish advice and the QA report
carries the count.

## Decided against or deferred

| Topic | Decision | Reason |
|---|---|---|
| Rent an AWS machine to speed up agent sessions | No | Most time is remote (model replies, image/video/voice APIs). Local render and QA would only drop from about 4 to 2 min per short. Use `pytest -n auto`. A big box only pays for many parallel workers. |
| Self-hosted image generation | No, stay on APIs + `agy` | About $0.10–0.50 of stills per video; rental startup and idle cost exceed that. Revisit above roughly $50–100/month or for a trained house-style LoRA. |
| Low-budget film pipeline (image-to-video first) | Deferred | Needs a lip-sync provider, character consistency, a shot-list planner and best-of-N takes. Start with a 30-second pilot comparing the budget API tier, a mid tier and a rented-GPU lip-sync model. A serverless GPU fits lip-sync and LoRA training. |
| Omniout plugin | Not needed | It adds LLM retry/fallback to app code; `video_editor_llm/router.py` already has it. It cannot change which model Claude Code uses. |
| Real SFX skill | Borrow the idea | Build cue placement natively from the Composition (item 2). |

Cost figures here are estimates from `pricing.yaml` and the discussion, not
benchmarks.
