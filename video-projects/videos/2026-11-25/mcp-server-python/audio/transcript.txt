MCP, the model context protocol, is an open standard for connecting AI apps to tools and data.
Think of it like a USB-C port for AI.
You write a server once, and Claude, VS Code, Cursor, and other apps can all use it.
Your server offers tools, and the AI decides when to call them.
We will use FastMCP, the most popular Python framework for MCP.
It is on version 4 now.
Following my UV video, this is a single file script, uvadd-scriptserver.pifastmcp.
That writes the dependency into the file, so there is no virtual environment to manage.
Here is the whole server.
We create a FastMCP app called mynotes.
Then each tool is just a Python function with the atmcp.tool decorator.
This one searches my notes folder for a word and returns the matching lines.
The important part, the type hints and the docstring are not decoration here.
FastMCP turns them into the description the AI reads.
So a clear docstring is how the AI knows when to use your tool.
The second tool converts kilometers to miles, kilograms to pounds, and Celsius to Fahrenheit.
And at the bottom, mcp.run starts the server.

Here is a read node tool that takes a file name.

An AI can be tricked into asking for exactly that.

The fixes tool lines, resolve the path, and diffuse anything outside the nodes folder
or anything that is not a markdown file.
Now the same request gets an error.
My rules never expose a tool that runs shell commands or takes any path.
Keep tools read only unless they must write,
and never put secrets where a tool can reach them.
